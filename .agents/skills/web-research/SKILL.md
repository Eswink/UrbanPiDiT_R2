# 外部检索（web-research）

## 何时使用

- 需要**本仓以外**的公开事实：第三方库用法 / 版本变更 / API 参考 / 论文 / 报错信息；
- 要判断某个上游项目是否已修复某问题、某数据源是否仍开放；
- 写进文档或报告的结论依赖外部信息，需要来源与访问日期。

**不适用**：

- **仓库内部**的问题（代码、产物、历史）→ `planner` / `Explore`；
- **数据获取**（ERA5、WeatherBench2 等）→ `real-data-acquisition`：下载需要显式授权、
  必须走 `data/download/` 的既有下载器；本技能**不授权任何数据下载**；
- **库的行为**：先读 `.venv` 里已安装的源码
  （`.venv/lib/python3.12/site-packages/<pkg>/…`）——那是一手证据，比检索更快更准；
- 一次性的、不写进仓库的随口查询（不值得委派；但结论一旦要引用，就回到本技能）。

## 前置条件

- 子智能体定义 `.zcode/agents/web-researcher.md` **已被 git 跟踪**（干净克隆上按名可委派）；
- 主链路没有 `WebSearch` / `WebFetch`：R-049 的闸门会拒绝，不要试，直接委派；
- 委派提示词必须自包含——该子智能体**看不到仓库**，凡需要它判断的仓库现状都要写进提示词。

## 步骤

1. **拆问题**：把「要查什么」拆成可独立检索的子问题；写清版本/环境约束（Python 3.12、
   torch 版本、地域），并说明你要的是**结论**还是**原文片段**。
2. **委派**（`Agent` 工具，`subagent_type: web-researcher`）。提示词模板：

   ```
   问题：<一句话>
   已知（来自本仓，你看不到，必须给你）：<相关配置/版本/现象，3–5 行>
   要什么：<每条结论附 URL；区分一手/二手；给出所见版本号或文档日期；
           冲突原样列出；查不到的进「未能确认」>
   不要：不要猜测、不要用记忆补全、不要大段原文
   ```

3. **回收**（关键）：子智能体的输出**不构成证据**。要写进仓库的内容按 R-050 处理：
   - 关键数字与结论**回到一手来源核对**：二次委派取原文短句，或用 `curl` 取原文；
   - 一手与二手分开标注；只有一个来源时写明「单来源」；
   - 「可达 / 不可达」必须**实测**：
     `curl -sS -I -L -m 5 -o /dev/null -w '%{http_code}' <URL>`，不采信搜索摘要。
4. **留痕**：写进文档时给出 `URL + 访问日期`；`curl` 取回的原文放 `outputs/web-research/`
   （未跟踪）；失败照记 `URL + 失败原因`（超时 / 403 / 需登录 / 反爬）。
5. **降级（子智能体不可用时）**：下列任一情形即视为「破产」——委派报错、模型不可用、
   超轮次、返回空、结论全部进「未能确认」。处置：**重试一次**（把问题拆得更小）；
   仍失败则改由主链路 `curl` 直取，并在记录里写明「web-researcher 不可用：<原因>」。
   抓不到的站点按步骤 4 照记，不得用回忆补全。

## 本机可达性（2026-09-28 实测，E-188；随时间与网络环境变化，用前重测）

| 主机 | 结果 |
| --- | --- |
| `api.github.com`、`docs.python.org`、`pytorch.org`、`arxiv.org`、`cn.bing.com` | HTTP 200 |
| `raw.githubusercontent.com` | **超时**——抓 GitHub 原始文件改走 `api.github.com` 的 contents 接口 |
| `www.google.com`、`duckduckgo.com` | 不可达 |

`https://cn.bing.com/search?q=` 可作**入口**（能返回结果列表），但摘要**不是证据**（E-184）。

## 检查点

- 委派提示词自包含吗？子智能体看不到仓库。
- 每条要引用的结论都有 URL 吗？一手/二手分开了吗？
- 关键数字回一手来源核对了吗？还是只信了检索摘要？
- 失败与不可达写下来了吗？
- 有没有用「我记得……」补一个其实没查到的结论？

## 常见失败

- **把检索摘要当证据**：E-184 有真实先例——`cn.bing.com` 对同一批查询返回过完全无关的结果；
- **把子智能体输出直接当结论**：它是检索结果，不是证据；引用前必须回一手；
- **用记忆补全**：查不到就写「未能确认」，不写「应该是……」；
- **绕过闸门**：主链路 `WebFetch` 会被拒绝（R-049），不要换个写法去试；
- **降级后不留痕**：`curl` 抓取同样要记 URL / 访问日期 / 失败原因，并写明为什么降级。

## 完成判据

- 每条写进仓库的外部事实都有 URL + 访问日期，一手/二手标注清楚；
- 关键数字经过一手来源核对（二次委派或 `curl` 原文）；
- 不可达与查不到的已如实记录；发生降级时原因已写明；
- 结论与推测在文字上分开，没有以断言形式出现的不确定说法。

## 明确不覆盖

- 不做科学判定：阈值、判据、DONE 定义在 `docs/rules/` 与已冻结的证据文档里；
- 不授权数据下载（`real-data-acquisition`），不写 `data/**`（R-004）；
- 不替代仓库内部检索（`planner` / `Explore`）；子智能体的输出不产生证据；
- 不保证可达性——本机可达性会变，用前实测。

## 规范示例（一次完整往返）

委派：

```
问题：xarray 是否改变过 open_dataset 对 zarr store 的默认 chunk 行为？从哪个版本起？
已知（来自本仓，你看不到）：只读本地 zarr store，不联网；版本以 .venv 为准。
要什么：每条结论附 URL 与文档日期；一手（release notes / 官方文档）优先；冲突原样列出。
不要：不要猜测、不要大段原文。
```

回收与留痕（写进文档时应当长这样）：

```
xarray 文档记录了 zarr 后端行为的变更（来源：https://docs.xarray.dev/en/stable/whats-new.html，
访问日期 2026-09-28，一手）。本仓实际版本以 .venv 中的源码为准
（.venv/lib/python3.12/site-packages/xarray/…，一手）。
"是否影响本仓"需要读本仓代码判断，未由 web-researcher 回答（未能确认）。
```

降级样例：

```
web-researcher 不可用（委派返回空；重试一次后仍空）→ 主链路 curl 直取：
$ curl -sS -L -m 10 -o outputs/web-research/xarray-whatsnew-20260928.html \
      -w '%{http_code}\n' https://docs.xarray.dev/en/stable/whats-new.html
200
（本次为降级取数，原因已记录；原文片段落 outputs/web-research/，未跟踪）
```
