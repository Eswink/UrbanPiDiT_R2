## Context

第一轮把 #71（时空输入）与 #72（RW-A 位置化读写）**一起**打开，并在文档里记下三条硬局限：
两个开关的**分别贡献 unresolved**；两臂**参数与算力不对齐**，赢面不能归因于机制而非容量；
只有 **2 个 seed**。本轮的任务就是把这三条按既有纪律逐条消掉，**不引入新机制**。

要回答的问题是窄的：**位置依赖本身是否超出它带来的容量改善？** 这要求一个对照臂与位置化臂
**模块相同、参数相同、算力相同**，唯一区别是「读取时 query 里还有没有位置」。第一轮的
`process.mean(dim=1)` 广播虽然位置无关，但它连模块都不存在，所以只能证明「旧机制差」，
不能证明「位置依赖本身有用」——这正是第一轮留下第 ②条局限的原因。

仓库既成事实（0013 已定）：任何 `model/*.py` 字节改动都会改变 `model_code_sha256`，
旧 checkpoint 在新代码下拒绝加载；因此新通路必须**默认关**且关闭时与改动前逐位相同。

## Decision

**采用：新增一个默认关的「池化 query」构造开关，用它构造与位置化臂容量完全对齐的控制臂；
四臂 × 三种子在同一新协议 digest 下从零训练，归因只压在 C−D 这一对上。** 具体：

1. **开关**：`PositionalProcessReadout.pooled_readout_query` 与
   `ProcessForecastCoReasoner.pooled_readout_query`，默认 `False`；非布尔值即
   `ValueError`，与既有开关同风格（`type(value) is not bool`）。**开启但不开启**
   `positional_process_readout` 时**直接报错**——一个被静默忽略的开关是配置错误，
   不是控制组。
2. **池化在位置编码之前**：取 `query_norm(context)` 的**按位置均值**后广播，
   **不**加位置编码。若在编码之后池化，编码自身的均值会混进控制臂，「读取无位置」
   这句话就不成立（目标源 §6 第 5 条已记录该更正）。
3. **开关不新增任何参数**：C 与 D 的张量名集合、形状、数值与参数总量完全一致
   （2,968,259）。实测前向 FLOPs 也**完全一致**（13.9046e9）——这与目标源 §4 第 8 条
   「池化把 q 投影从 N 个位置降到 1 个位置、FLOPs 会略低」的**预期不同**：本实现把
   均值广播回 N 个位置后仍由 attention 自己的 q 投影逐个投影，所以投影仍是 N 次。
   **如实报告**，并把这一点写进证据文档：这使 C−D 成为**参数与算力双重对齐**的对照，
   而不是「算力略低」的对照。
4. **四臂**（同一 M2 store、同一 400-update 协议常量、全部从零训练）：
   A `process_pooled`（两开关全关）、B `process_spacetime_only`（只开时空输入）、
   C `process_spacetime_rwa`（全开）、D `process_rwa_capacity_control`（全开 + 池化 query）。
5. **臂配对是实测**：四臂同 seed 构造，六个臂对的共享张量逐位比较；锚臂 `state_dict`
   用训练器**自己**的转移规则**真的加载**进其余三臂，加载后逐张量比对，`applied/ignored`
   计数写进产物；训练报告里的计数若与实测不符即失败。
6. **一个协议、十二个 run**：协议在每个 seed 第一次 `optimizer.step()` 之前写盘并回读校验；
   12 条 (seed, arm) 训练记录各自携带 `protocol_sha256`，合并时要求十二个值全同。
7. **判定规则不变**：#60 比较器、`depth=0`、逐 seed 同号才 improved/worsened，其余
   unresolved；**不新增阈值、不放宽判据**。C−D 若 unresolved 或方向相反，
   结论写「位置依赖本身未获支持」，不得换变量或网格去凑赢面。

## Consequences

**变容易的：**

- 「机制 vs 容量」这个混淆第一次有了可机械核对的对照：C−D 在参数、模块、算力上完全相同，
  差别只有 query 里有没有位置；`pooled_readout_query` 成为一个可复用的控制旋钮。
- 四臂配对是**实测 + 加载后逐张量比对**，不是按名字推断，臂数从 2 增到 4 也没有退回假设。
- 第一轮的第 ②条局限（不能归因）在本轮**对 C−D 这一对**被消掉；第 ①条（不能分离两个开关）
  由 A/B/C 三臂消掉；第 ③条由三个 seed 部分缓解（仍不是显著性）。

**变难 / 代价（如实列出）：**

- **只有 C−D 是容量对齐的**：A 与 B/C/D 之间仍差参数与算力（B +19,488 参数 / +0.65% 前向
  FLOPs；C/D +168,480 / +8.26%），所以 A 参与的任何配对仍然混着容量，不能当机制归因。
- 池化 query **不省算力**（仍投影 N 次），因此这个控制臂不是一个「更便宜的近似」，
  而是一个纯粹的位置消融；想要省算力的实现（先池化再投影）在数学上等价但会改变
  浮点求和顺序，本轮刻意不采用，因为那会让 C−D 同时差着算力。
- 三个 seed 给的是**一致性**而不是显著性；本轮**不引入**任何显著性阈值。
- 控制臂只消掉**读取处**的位置依赖：位置信息仍可经 context 自身进入模型（A 也有同样的通道），
  所以 C−D 测的是「读取是否要看位置」，不是「模型是否用到位置」。
- 时空输入在 C 与 D 上都开着，两个机制**没有**在本轮重新分离；交互项（第五臂）明确不做。

**备选方案与否决理由：**

- *在位置编码之后池化*（目标源草稿写法）：否决。编码的均值会留在控制臂里，
  「读取与位置无关」这句话就变成近似而非构造性质，D4 的两条钉住测试会失去意义。
- *先池化再投影（q 只算 1 次，省算力）*：否决作为本轮定义。线性层下
  `q(mean) == mean(q)`，两者只差浮点求和顺序与算力；选省算力的写法会让 C−D 同时差着算力，
  刚好重新引入本轮要消掉的混淆。
- *用「池化的广播投影」作控制臂但复用第一轮 checkpoint*：否决。`model_code_sha256`
  与 `protocol_sha256` 都不同，硬约束禁止把不同 digest 的格子拼进一张表。
- *2×2 全因子第五臂（`spacetime_inputs=False + readout=True`）*：本轮不做。
  交互项只有在 C−D 有定论之后才有解释价值（目标源 §7）。
- *把 D 臂的读数零初始化以让两臂初始等价*：否决，同 0013——那会让「池化真的被钉住」
  这类初始化态探针无法成立。
