# 0030 实验、节点推进与普通决策常设下放，总体方向归用户

- **日期**：2026-10-02
- **状态**：accepted

## Context

用户在决策 0029 之后进一步明确：「推进权和实验权，普通决策权全部下放给你，注意，我只需要负责
总体实验的方向！」此前 0029 仍把节点推进交给用户/独立复核，0025 第 5 条仍要求每轮用户触发，
主计划和 goal-loop 还要求每轮结束即停。这些现行限制与本次书面授权冲突，需形成可检索的接续契约，
而不是仅靠新窗口解释旧文字。用户随后批准本轮只实施治理与 goal 交接，不执行实验或关闭 issue。

本决策取代 `0029-standing-experiment-delegation.md`，完整继承其实验、时长与记账契约，并取代
`0025-campaign-master-plan-and-per-round-recheck.md` 第 5 条的逐轮用户触发限制及第 4 条中
普通节点选择需要用户许可的解释。0025 的唯一主计划、每节点对表、证据登记和机械门禁仍有效。
决策 0021 → 0029 → 0030 的正文和引用链保留；旧运行的预算、终态与停止事实不回溯改变。

## Decision

1. **方向与普通决策分工。** 用户把控总体研究目标与研究方向。该方向内的本地 GPU 实验、训练/评估、
   实验 workflow、训练规模、每次时长/预算、普通工程与方法选择、故障排查、协议编排和节点推进，
   均由执行者自主决定并留痕，不逐次 `AskUserQuestion`，不逐节点等用户许可。
   普通选择须先于运行写定，影响长期约定的选择仍写 ADR；普通方法选择不包含事后改变冻结科学判据。
   总体方向需改变或碰到保留授权边界时，停止相关动作并交用户决定。
2. **会话内连续推进。** 同一个已启动的 goal 可按主计划连续完成多个节点，不再每轮结束等待用户重新
   触发。每节点前后仍对表并登记证据、账本和下一动作；执行者按既有前置/出口决定下一允许节点并
   一致更新 `current_node`。独立审阅是证据质量检查，不是推进许可；不能用机械绿灯替代节点实验
   或科学门禁。真实失败立即停止该次运行、全额记账；新修复/补测可自主另立具名协议与新输出，
   不修改旧失败为成功，也不绕过仍有效的不可分辨/不能归因等停止线。无后台守护、cron 或脱离
   当前 goal 的自动续跑；会话终止后据进度交接，不自行新建定时会话。
3. **继承时长与会计契约。** 每次实验先把范围、产物、失败/skip 处理及两个数值端点写进长文和
   冻结 `protocol.json`：`planned_seconds` 为软预算，`hard_cap_seconds` 为宽松硬上限，默认约
   2× 计划。按整轮墙钟计 CPU 前置、训练、评估、启动/间隔与清理；超软预算继续并记录
   `soft_overrun_seconds`，仅硬上限因时长截断，记 `budget_limited`/`failed` 并全额记账。
   真实错误和身份/资源门禁仍可提前停止。承载新实验的 CI 须满足
   `timeout-minutes * 60 > hard_cap_seconds` 并留收尾余量，按需要提高数值而不删时限。
   不设总 GPU-h 上限；cap/used/remaining 仅会计字段，逐行实际成本与证据指针及 C-02 算术不变，
   账本耗尽不单独停止。无新实验时不批量改 workflow 数值。
4. **保留授权与硬约束。** GPU 租赁/付费资源、新或多年度数据下载、数据发布 `--write`、独占 GPU、
   main 合并、破坏性操作仍按原边界取得具名授权；force push、`--mirror`、删默认分支、绕 hook
   仍禁止。R-006/R-028/R-054/R-009、原始数据与归档只读、禁止合成回退、`model_code_sha256`/
   source SHA256/`BUILD_COMPLETE` 身份校验、`scientific_claim: false` 与 limitations 均不豁免。
   默认共驻，启动和每次 spawn 只读 UUID/余量，不向邻居发信号。skip/cancelled/queued/partial/failed
   不算通过。冻结常量（含原 1800 秒）、历史协议/≤30 min/失败事实、证据页和归档不得回写。
5. **具名路线与关闭范围。** 本次总体方向仍为计划 0009 的主模型 V2 收尾：N2a 补全 → N3 → N4 →
   N5/关闭。N3/N4 的普通推进不再需额外询问；matched-Generic、两步可微 rollout、确认轮与 adaptive
   的冻结前置仍有效，adaptive 默认不启动。继承计划 0009 已写明的 #70–#75 关闭授权，本决策作为
   该具名范围的禁令解除记录：现行主计划的「不动 main/不关闭 #70–#75」仅在 N5 证据齐备、验收
   支持相应 verdict、前置齐全、工作分支精确 SHA 主 CI 九步成功后，允许用 `Closes` 提交非 force
   ff 推 main，并匿名核 issue 终态。这不是 main 合并许可，不扩展到其它 issue；证据不足保持
   BLOCKED/开放，不为全部关闭弱化测试。旧长文的禁止项是当轮事实，不回溯删除，由新目标声明
   后续执行适用本决策。新 goal 长文见 `docs/goals/v2-autonomous-completion-and-closeout.md`。
6. **判定权限与诚实。** 执行者可依据冻结判据写出工程、实验与科学证据的正/混合/负结论，不能
   把研究期望当作事实或把 CI/关闭 issue 当成科学成功。普通节点调度无需最终 goal verifier 逐节点
   放行；最终 goal 的 `complete` 仍由运行时独立完成校验或用户裁定，执行者不得直接改状态或
   自宣目标完成。遇到已有科学停止线先如实登记并停相关探索，不靠追加 seed/预算「练到赢」。

## Consequences

**变容易的：** 用户只需把控方向，不再负责微观排障、时间分配与逐节点许可；一个 goal 可连续推进
已有路线，减少人为停顿。每个节点仍有独立证据与对表，不以聊天中的临时同意代替运行协议。

**变难 / 代价（如实列出）：** 用户不再逐次看到普通决策，执行者承担方法选择、成本累计与偏差
控制责任；无总上限和连续推进可能累积额外 GPU-h 与方向偏差。每个决定的理由、实验身份、实际
成本、失败与未做项必须可追溯；独立审阅不可省成单纯测试计数。旧 prepared 长文仍含历史许可
文字，新窗口需使用新接续目标而非复制旧 objective。最终完成校验仍是 best-effort，不能伪称自动结项。

**备选方案与否决理由：** 保留逐轮用户触发/节点许可被用户明确否决；把独立审阅改成新的逐节点
授权闸门不采用，那会恢复同一停顿。把普通决策权解释成任意改变总体方向、事后放宽判据或租卡/
数据/main 合并许可不采用，超出书面范围。自动后台调度/无限重试不采用，会违背失败与资源纪律。

本轮只落上述治理和交接文档，0 GPU-h，不运行 N2a/N3/N4/N5、不关闭 issue、不写 main。
