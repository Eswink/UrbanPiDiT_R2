# 0067 — 执行文件清单必须是具名清单，不得对包目录做活体 `rglob`

- **日期**：2026-10-28
- **状态**：proposed
- **约束对象**：R2–R5 与**未来任何轮次**的新驱动；**不**回头修改任何已冻结轮次，见 Decision 第 4 条
- **范围**：所有用 `execution_files()` 把源码身份绑进 `protocol.json` 的实验驱动。
  **不改**任何已冻结协议、不改任何在跑的轮次、不改 `data/raw|interim|processed`。
- **依据**：决策 0065（R1 seed43 的那次真实事故与重放处置）；
  `scripts/study_r7_s3_v3_rollout_ft_worker.py:31-37`（缺陷实现）；
  `scripts/study_r7_s3_fy_year_coverage_matched.py:275-280`（发作点）；
  `AGENTS.md`「禁止绕过 checkpoint / 数据身份校验……不能修改比对逻辑」；
  `.agents/skills/pinned-artifact-replay/SKILL.md`（旧产物用归档代码重放）。

## Context

**① 事故是真实的，而且已经吃掉了钱和两天墙钟。** R1 的 seed41/seed42 各跑完约 11.7 h
（实测 89,519.6 s / 88,362.4 s）之后，seed43 在 **20.76 s** 内 exit 1：

```
File ".../scripts/study_r7_s3_fy_year_coverage_matched.py", line 279, in validate_protocol
RuntimeError: incomplete execution source inventory
```

**② 根因是"清单口径"，不是"源码变了"。** `execution_files()` 的实现是：

```python
for directory in ("training", "model", "data"):
    names.extend(str(path.relative_to(ROOT)) for path in (ROOT / directory).rglob("*.py") ...)
```

它对三个包目录做**活体**递归扫描。本轮冻结时是 **195** 个文件；等到 seed43 启动时，
**另一条互不相关的研究线**（城市静态协变量轮，决策 0063/0064）在 commit `7065f19`
新增了 2 个模块，于是清单变成 **197**，`set(...) == set(...)` 立刻不成立。
实测：**195 个冻结条目逐位未变、无删改**，差集**只有新增**
（`data/download/urban_static_sources.py`、`data/preprocess/urban_static_aggregate.py`），
且**没有任何冻结清单内的文件 import 它们**。

**③ 这个身份表面比它想保护的东西大得多。** 195 项里 **182 项来自 glob**
（`training/` 92、`data/` 57、`model/` 33），只有 **13 项是具名**
（12 个 `scripts/` + 1 个归档 `protocol.json`）。也就是说，93% 的"身份"是
"目录里当时恰好有哪些 `.py`"，而不是"这一轮真的执行了哪些代码"。
⇒ 任何无关研究线往这三个目录加一个模块，都会让**已经跑完的轮次**在最后一次校验处整轮失败。

**④ 失败形态特别贵。** 它在**每阶段开头**校验（`worker()` 的第一步），
所以在 seed 阶段发作时：前面 seed 的 GPU 时间已经花掉、后面的 seed 还没跑，
而**结论一个字都拿不到**。R1 实际代价 = 约 49 GPU-h 已花出的成果险些作废
+ 一次归档重放 + 两天墙钟。这不是"晚一点报错"，是"最贵的时间点报错"。

**⑤ 为什么不能现在就修 R1 的驱动。** 驱动本身在 195 个冻结条目里，
改它必然改变 `execution_files_sha256` ⇒ 等于重写已冻结协议，
会让 seed41/42 的成果按决策 0045 白名单规则**不可复用**（`protocol_sha256` /
`code_zip_sha256` 都在白名单内）。这也是决策 0065 选择"归档重放"而不是"修代码"的原因。

## Decision

1. **新驱动的执行文件清单必须是具名清单。** 不许对 `training/`、`model/`、`data/`
   做 `rglob("*.py")`；必须**逐条写出**这一轮实际 import 或实际执行的模块路径。
   允许用"从本轮入口做静态 import 闭包"的方式**生成**清单，但**生成结果必须落进
   `protocol.json` 的明文**，且下次运行时**按明文比对**，不再重新 glob。
2. **清单的语义是"本轮执行了什么"，不是"仓库里有什么"。** 判据：
   若某个文件改动**不可能**影响本轮的训练/评分结果，它就不该进清单。
   按这条判据，`data/download/urban_static_sources.py` 这类与本轮无关的下载器**本来就不该**在内。
3. **不变量要在两处都断言**（缺一不可）：
   ① `set(declared) == set(actual_closure)`（防止漏写/多写）；
   ② 逐文件 `sha256` 相等（防止内容漂移）。
   现有的 `validate_protocol` 已做 ②，缺的是把 ① 从"活体 glob"换成"本轮闭包"。
4. **不回头修改已冻结轮次。** R1 的驱动保持原样（它的协议必须保持可读、可重放）；
   任何对 R1 的补跑继续走决策 0065 的归档重放。本条只约束**尚未冻结**的轮次
   （R2–R5 及以后）。
5. **R2–R5 的测试必须含一条反证**：往 `training/` 或 `data/` 里**新增**一个 `.py`，
   断言本轮的 `execution_files()` **不发生变化**。没有这条反证，缺陷会静默回归。

## Consequences

**变容易的：**

- 一条无关研究线的提交不会再打崩一条在跑的轮次。这是本条的全部目的。
- 清单从"195 项、93% 靠猜"缩到"本轮真正执行的几十项"，`validate_protocol` 的
  重哈希成本与误报率同时下降。
- 事故的**归因**变清楚：清单不等时能立刻区分"我执行的东西变了"（真问题）
  与"别人往目录里加了文件"（假问题）。

**变难 / 代价（如实列出）：**

- **具名清单会漏。** 活体 glob 的好处正是"不会漏掉新 import"；改具名后，
  如果有人新增了 import 却忘了加清单，身份表面就会出现**缺口**——这比"过宽"更危险。
  缓解：Decision 第 3 条的 ① 用"本轮 import 闭包"生成并断言，而不是靠手写；
  且必须保留逐文件 sha256。
- **闭包生成本身要正确。** 若闭包算法漏掉动态 import（`importlib`、按字符串 import），
  漏检就回来了。缓解：本轮这类动态 import 只有一处（归档 `protocol.json`），
  已具名在内；以后新增必须在测试里显式覆盖。
- **有些轮次确实依赖"目录快照"语义**（例如"这一轮的代码身份 = 整个 model 包"）。
  改具名会让这类轮次的身份**变窄**。代价是以后"改了某个没人 import 的模块"不再导致失败——
  这**正是想要的**，但要在证据页写清楚"身份表面已收窄"。
- **本条是 proposed**，不是已生效的阻塞规则：它还没有进 `tools/check_conventions.py`。
  在它被机械化之前，**只能靠人读驱动来执行**。这是本条的已知弱点，如实记在这里。
  **补记（2026-10-28，同一会话内推进）**：Decision 第 1–3 条已由
  `tools/r7_explicit_inventory.py` 落成可运行的实现（`import_closure` /
  `explicit_execution_files` / `inventory_faults`），第 5 条要求的反证在
  `tests/test_r7_explicit_inventory.py`（12 项全过）。**实测**：对 R1 的真实驱动，闭包
  **89** 个文件（对照 glob 的 **182**），不泄漏 `tools/`、`tests/`、归档快照，
  且**覆盖运行时实际导入的全部 15 个仓内模块**（用 `sys.modules` 交叉核对，0 遗漏）；
  在同一棵树上新增一个无关 `data/*.py`，闭包**不变**，而 R1 的 glob 形状**从 184 涨到 185**。
  **仍未做**：把它接进 `check_conventions.py` 作为阻断规则——那要先决定强制点落在哪
  （冻结时断言，还是提交闸门）。因此本条状态仍是 proposed，不是已生效规则。
- 一次真实事故的教训，代价已经付出（约 49 GPU-h 的成果险些作废、两天墙钟、
  一次归档重放）；本条只负责让它**不再重演**。

**备选方案与否决理由：**

- **备选 A：现在就改 R1 的驱动，把 glob 换成套具名清单。** 否决：驱动在 195 个冻结条目内，
  改它 = 重写已冻结协议的 `execution_files_sha256` ⇒ seed41/42 按 0045 白名单不可复用，
  且会破坏可重放性。已冻结的东西不改，这是仓规。
- **备选 B：把 `validate_protocol` 的集合相等放宽成子集（`frozen ⊆ actual`）。**
  否决：这会把一条真实的完整性检查变成永久漏洞（少了文件也会静默通过），
  且 AGENTS.md 明文禁止修改比对逻辑。
- **备选 C：维持 glob，但把 glob 的目录范围收窄（例如只扫本轮 import 的那几个子目录）。**
  部分可行但不彻底：只要还有任何目录级扫描，就还有"别人加文件把我打崩"的可能，
  只是概率变小。且"该扫哪些子目录"仍需人工判断，没有比具名清单更省事。
- **备选 D：什么都不做，把这次当作一次性事故。** 否决：事故的根因是**结构性**的，
  下一次任何研究线往 `data/preprocess/` 加一个文件都会重演，
  而 R2–R5 还有四轮要跑，且它们的预算（每轮数十 GPU-h）比 R1 更高。
