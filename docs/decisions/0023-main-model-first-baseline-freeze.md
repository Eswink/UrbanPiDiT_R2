# 0023 主模型优先与基线冻结：开发期门禁与发表期门禁分开

- **日期**：2026-09-29
- **状态**：accepted
- **依据**：issue #70 的正文与评论（2026-09-27）；`docs/R7_ROADMAP_GATE_STATUS.md`；
  `docs/R7_B1_D1_COMPARISON.md`、`docs/R7_B2_MULTISEED.md`、`docs/R7_B3_SCALE.md`、
  `docs/R7_69_BUCKET_EXPANSION.md`；`docs/R7_71_72_*` 三轮

## Context

**这是要解决的问题**：本仓同时存在两条互相拉扯的判据——「主模型必须有效」与
「基线必须先被全面超过」。前一条写在 issue #70 的目标里，后一条写在 issue #1 的
G1–G4 与 `docs/R7_ROADMAP_GATE_STATUS.md` 里。两条都没有错，但**没有说清它们分别管哪个阶段**，
于是出现了一个谁也没打算要的后果：**基线不够强时，主模型的结构改动被卡在门外**，
而基线的边际信息已经很低。

**事实基础**（全部有据可查，不是印象）：

- G1–G4「没有一条被正面支持」（`docs/R7_ROADMAP_GATE_STATUS.md:18-20`）。
- B1（`fa8dd68`）：在 t2m 上，四个神经臂在**每一个时效**都输给零参数的 train-only 气候态。
- B2（`94828da`，预注册阴性）：gate 未达成；72h 的 seed 间扩散 20–23%（单个格到 65%）。
- B3（`eba90e0`）：容量扩到 6.47×（18.12M）后，85 格里只有 41 格改善，唯一表面收益
  在 seed 间不一致；「没有任何 ours-wins 声明」。
- M2（`docs/R7_69_BUCKET_EXPANSION.md`）：桶 4→8 后气候态在 t2m 上仍胜 74/75 格；
  全表 705 优于/570 劣于；process vs generic = 2 改善/12 恶化/**71 未决**。
- 与此同时，**主模型自身的结构瓶颈已被定位到代码行**：`process.mean(dim=1)` 后广播
  （`model/process_forecast_r7.py:182` + `model/recursive_weather_r7.py:33`）；
  `process_readout` 在 `process_weight=0` 时**从未被训练过**（`docs/R7_65_PREDIAGNOSTIC.md`）；
  位置化读取的位置依赖本身**未获支持**（二轮 C−D = 8/13/64）。
- 也就是说：**「再加一个基线」不能回答任何一个当前问题**，而「改主模型的读写路径」能。

**为什么现在必须落成决策记录，而不是继续写在 issue 里**：这条政策目前只存在于 GitHub
issue #70 的正文中。而本仓已记录**会话内没有 GitHub 写通道**（API 写 401、无 `gh`，决策 0011），
issue 正文**不在版本控制内**、不受 R-037 约束、CI 不会读、未来会话的 agent 也不会自动加载。
一条只活在 issue 里的长期研究策略，等于一条**只对读过那个 issue 的人存在**的策略。
把它写成 ADR 是为了让「开发期门禁是什么」成为可被 agent 加载、可被评审、可被追溯的治理文本。

## Decision

1. **基线冻结（测量工具，不是竞赛）。** 已审计的六个基线（persistence、train-only
   climatology、U-Net、window/Swin-like、AFNO-small、generic recursive）连同其冻结配方
   视为**测量仪器**：不再新增 baseline family，不再做容量/配方的第二轮搜索，不再为「让基线更强」
   推迟主模型实现，也不再重跑已完成的基线战役。
2. **主模型是关键路径。** **工程通过**（forward/backward/形状/梯度/测试/resume 正确）即足以运行
   一个主模型假设的定向实验；**基线尚未全面胜出不再是该实验的前置条件**。
   主机制先看 +6/+12h，+24/+48/+72h 一直保留为诊断，长时效退化不得隐藏。
3. **「匹配 Generic」是强制归因对照。** 任何「过程结构有用」的声明都必须带一个
   **同结构、同已知输入、无过程语义**的 Generic 臂。若主模型新增了已知上下文或共享 decoder，
   就必须给 Generic 对应的共享结构/输入；否则该实验只能主张「整体系的改善」，
   **不能把新增容量或信息归因为过程语义**。
4. **开发期实际保留的对照恰好五个**：旧 Process 模型、新 Process 模型、匹配 Generic、
   persistence、当前 train-only climatology。日常开发不再扩大这个集合。
5. **发表期门禁不变。** 完整强基线表在**发表阶段**按冻结配方重跑一次；G1–G4 不被删除，
   而是**重新定位**到发表阶段作为对外主张的门槛。
6. **本决策不放宽任何已记录的负结果、已冻结的阈值或任何判据。** 它改动的是**门禁的适用阶段**，
   不是门槛的高度。已冻结的协议、单位修正（决策 0010）、比较器（#60）与三 seed 只给一致性的
   规则全部照旧。
7. **每轮实验仍然必须**：有自己的固定假设、有界预算与案例选择，并在第一次优化器更新前冻结协议
   （R-006）——「主模型优先」不豁免这条。

## Consequences

**变容易的：** 主模型改动可以在基线尚未全胜时进入实测，实验循环从「先证明基线被超过」变成
「直接检验机制假设」；对照集合固定为五个，每轮的准备工作可复用；把「我们为什么现在不改基线」
写成可追溯的文本，未来会话不会把「基线还输给气候态」误当成停止改主模型的理由；
强基线表的成本被明确推迟而不是被悄悄取消。

**变难 / 代价（如实列出）：**

- **开发期的数字不再与已冻结的基线表可比。** 基线冻结之后，任何新的主模型结果都**不能**直接与
  B1/B2/B3/M2 的表格并置（协议 digest、模型 code digest、预算、数据 identity 不同）。
  这让「我们的方法现在有多好」在开发期**无法回答**，必须等到发表期的重跑。
- **「匹配 Generic」是一条要长期维护的并行配置路径。** 主模型每加一个结构，Generic 也要能挂同款
  骨架，否则归因不成立。这条路径本身是**漂移风险的来源**（三处 step 实现各写一份的既有问题
  就是同类）——缓解手段是共享 step 函数 + 等价性测试，而不是靠纪律。
- **发表期的成本只是推迟，不是免除。** 届时需要一次性重跑完整强基线表，且要在**新的冻结 test** 上做，
  这仍然是一笔真实的数据与算力预算（#75 已写明「出现可复现主模型改善后，才为最终独立年份/季节
  扩数据和正式测试申请一次明确预算」）。
- **外部有效性风险。** 如果主模型机制在小数据/小规模上成立但最终没有可复现改善，那么本决策省下的时间
  换来的是「我们没能在开发期用强基线定位自己」——这个风险是真实存在的，必须在论文里如实披露。
- **可能被误用。** 「基线冻结」很容易被读成「基线不重要」或「不用报告基线」。**不是**：
  persistence 与 train-only climatology 仍在每一轮里出现，且每一轮都必须报告它们。
- **判据的重新定位需要外部复核。** G1–G4 从「开发期门禁」改述为「发表期门禁」，属于对既有文字
  作用域的重新解释；本决策把它写死，但这一步仍是最需要被第三方复核的地方。

**备选方案与否决理由：**

- **照旧「基线先全胜再改主模型」**：被否决——B1/B2/B3/M2 已把该路径的信息榨干，
  继续下去只是重复已知结论，而主模型的瓶颈已经被定位到具体代码行。
- **完全放弃基线、只报主模型**：被否决——那样连「比 persistence 和气候态好」都无法回答，
  且会丢掉本仓最有价值的一类负结果（climate 压倒 t2m）。
- **把政策留在 issue #70 里**：被否决——issue 正文不在版本控制、CI 不读、agent 不加载，
  等于没有治理文本（决策 0011 已记录本机无法写 issue）。
- **改 G1–G4 的门槛数值**：被否决——那是放宽已冻结的判据；本决策只改**阶段归属**，不改数值。
