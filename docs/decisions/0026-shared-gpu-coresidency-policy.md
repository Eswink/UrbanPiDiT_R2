# 0026 本机 GPU 默认共驻与只读余量取卡政策

- **日期**：2026-10-01
- **状态**：accepted

## Context

用户在 N1 成本补测修复轮的准备期决定，本机 GPU 实验默认使用空闲显存共驻，而不是等待整卡空闲或要求
腾卡。既有补测守卫遇到非本实验 PID 就拒绝，不能表达这个决定。原首项实测峰值 allocated/reserved 为
39,590,400/46,137,344 B；2026-10-01 的两卡只读余量观测见修复轮长文 §1.2。

此决定只改变设备占用政策，不改变冻结科学判据、checkpoint/source 身份校验、逐项零 allocator 基线、
实验授权或预算。决策 0021 仍约束每次执行，N1 保持 paused，不因工程补齐而推进节点。

## Decision

1. 本机 GPU 实验默认共驻，使用空闲显存；不要求整卡空闲，不要求用户腾卡。
2. 启动前、每次实验子进程 spawn 前以只读查询核对物理 UUID 与显存余量。余量门槛必须在协议中预声明；
   N1 v2 采用 ≥2048 MiB，启动选卡时两卡均不足只可有限只读等待（间隔 ≤60s、总时长 ≤600s）。
   外部 PID 只作记录，不是拒绝依据；读数不是显存预留，执行期间不足仍失败即停。
3. 禁止对任何非本实验进程发送任何信号（包括 SIGSTOP/SIGCONT/SIGTERM），禁止实现冻结、终止或抢占他人
   作业的自动化。不建立常驻轮询守护或自动调度。截止时间清理只允许针对本轮直接创建、仍持有句柄的子进程。
4. 独占需求必须先取得具名授权，写明设备、范围、预算、停止条件；独占授权本身不授权干预他人进程。
5. 计量记录本进程 allocated/reserved 峰值、设备 UUID、启动前余量与邻居 PID；共驻可能影响墙钟时间，必须
   写入 limitations。墙钟值不剔除，不构成新的科学接受判据。授权、协议冻结、禁网与失败全额记账照旧。

## Consequences

**变容易的：** 余量够即可执行有界实验；不会因邻居存在而无谓等待，不需要腾卡，也不需要邻居具备 resume。

**变难 / 代价：** 只读门槛有查询与 spawn 之间的竞争窗口，不能保证后续显存可用；共驻可能改变墙钟时间，
成本结果必须披露这一限制。余量不足可能使实验失败，仍全额计费、不自动重试；协议多维护设备/余量证据。
此政策没有新的全仓机械安全闸门，禁止信号与独占授权仍依靠代码审阅、定向反证测试和执行记录。

**备选方案与否决理由：** 默认独占被否决，因为小实验显存远低于两卡可用余量且用户明确选择共驻；冻结邻居
被否决，因为冻结不释放其显存；终止邻居被否决，因为会破坏其作业且本轮没有此授权。对进程残渣调用私有释放
API 不作为评估计量修复，零基线继续由逐评估新进程构造保证；私有 API 只用于具名原因探针。

细则见 `docs/rules/gpu-resources.md`（R-054），用户决定与起点证据见 E-216、
`docs/goals/n1-cost-supplement-repair.md` §1.2/§2/§5。
