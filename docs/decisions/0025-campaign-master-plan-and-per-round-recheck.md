# 0025 campaign 主计划与每轮对表（机器可查部分交给 CI）

- **日期**：2026-09-30
- **状态**：accepted

## Context

R7 主模型（#70–#75）是按轮次推进的：每轮一份 goal 长文，轮末在 §8 写下「下一动作」，下一轮据此开工。
到 2026-09-30 已经这么跑了五轮（M1/RW-A、第二轮、第三轮、RW-B pilot、RW-B 减法），
但支撑它的三件事**全部是人工的**：

- **下一动作的时效无人核对**：`docs/R7_TASK_QUEUE.md` 停更于 2026-09-28（CI 数字已过期一个数量级），
  `docs/goals/full-auto-campaign.md` 的状态行被后续事实推翻，没有任何工具比对「主计划当前节点」与
  「上一轮 §8 的下一动作」。
- **GPU 账本不可复算**：结余（20.701 → 20.288）是手写散文；证据索引只覆盖其中两轮，逐轮数字散在
  各证据页里，没有脚本累加或对账。
- **goal 长文的结构检查不设防**：`tools/check_goal_brief.py` 只查结构、非阻断、不进 CI；
  上一轮用户粘进 `/goal` 的 objective 是**截短版**（不带交付物清单），verifier 因此读不到判据——
  这正是 R-034 警告的情形。

同时，用户明确要求把长期迭代下放给代理，但「每轮不能跑偏」——需要一个**唯一的主计划**与
**每轮开工前的对表**。仓库自己的纪律又禁止后台续跑（`docs/R7_MANUAL_ITERATION.md:3-6` 的用户决定），
所以对表必须发生在**每一轮开工的那一刻**，而不是某个后台循环里。

## Decision

1. **主计划是唯一权威**：`docs/goals/main-model-v2-campaign.md` 持节点图、对表清单、预算账本与进度块；
   每轮的目标长文是它的**派生物**，必须写明自己实现的是哪个节点（`<!-- round-node: X -->`）。
   `docs/R7_TASK_QUEUE.md` 对 V2 这条线不再维护，保留原位只作历史（不回溯改写）。
2. **每轮开工前对表六条**（节点一致性、账本算术、上一轮登记、objective 派生、判据未改动、不同意就停），
   其中第 1–3 条由 `tools/check_campaign_state.py` 机器执行（规则号 `C-01`…`C-06`，
   属该工具自己的命名空间），**接入 CI 为可失败的步骤**；第 4–6 条是人工动作。
3. **账本逐行必须有证据指针**；有证据索引记录的行做数值交叉核对，没有的行**如实列为 note**，
   不得被当成已核。把索引补成全量账本是将来可做的一件事，本决策不要求。
4. **对表只证明「不矛盾」**：工具通过不等于方向正确；科学方向仍由用户与独立复核裁定（决策 0021/0023）。
5. **迭代仍逐轮触发**：每轮结束给出「对表结果 + 下一轮提示词」，用户触发后开下一轮；
   解除或修改这条需要用户新的明确要求。

## Consequences

**变容易的：** 「跑偏」有了可指认的形态——节点不一致、账本对不上、上一轮证据没登记、长文缺交付物清单，
四类都会在 CI 里红；主计划成为单一入口，新会话不必在五份文档里找「下一步」；账本的每一行都能追到证据。

**变难 / 代价（如实列出）：**

- 每轮多一步对表开销，且主计划本身成了需要维护的活文档：节点图写错，机器检查会把错误**一致地**传播；
- 工具只覆盖机械部分（`C-01`…`C-06`），**不覆盖**「这一节点是否真是正确的科学下一步」——
  这仍是人的判断，工具无法替代；
- 账本里没有索引记录的行只能列为 note，意味着「无机器支撑的数字」会长期存在，除非另立一轮把它们补齐；
- CI 作业由八步变九步，历史证据页里的「八步」表述与新作业不再逐字一致（保留为历史实测，不回溯改写）；
- 走 `check_campaign_state.py` 的检查依赖两份文档的写法（状态块、`record:` 引用、`round-node` 标记），
  写法漂移会让检查静默降级为 note。

**备选方案与否决理由：** 「复活并改写 `R7_TASK_QUEUE.md` 当主计划」被否决——它是历史关卡板、
每一行都被后续文档引用，改写它会制造第二处真相；「只写纪律、不加机器检查」被否决——本仓已有五轮
证明纯纪律会漂移（账本、下一动作、objective 长度都是人写的）；「用定时任务/后台续跑实现连续迭代」
被否决——与用户 2026-09-23 的显式决定冲突，且 harness goal 的自动续跑已因校验器缺陷降为 best-effort（决策 0024）。
