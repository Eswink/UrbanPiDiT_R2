# 0036 按实际FP32运算核训练损失，失败聚合只独立零GPU补全

- **日期**：2026-10-03
- **状态**：accepted

## Context

B独立协议9f76e6e3…5e62b02完成六训练、三十验证，所有worker成功；聚合器在训练目标校验失败，
原attempt仍failed/finalized=false。检查器用Python binary64重新组合已经从FP32 tensor导出的L6/L12，
却采用物理指标的1e-9相对容差。原训练明确执行FP32的L6 + 0.5 L12，不是binary64目标。
实际400条两步损失逐运算round32重构全部严格相等，binary64比较拒绝其中99/88条。

完整计算已经完成，不应为了修元数据算法而重训或重复三十评估；也不能把原失败改成成功，或
修改旧protocol/code.zip/checkpoint/receipt。0030/0032允许普通合法修复；0031的逐来源独立补全
原则可用于统计，但其M3科学暂停与旧证据完全不改。

## Decision

1. 活跃聚合器前瞻校正训练目标的运算域，重构FP32乘法及加法逐次舍入；有限性和数字类型仍拒绝
   非法输入。原tables.close、物理指标、科学端点、种子、更新数及选择规则一概不放宽。
2. 增加真实FP32案例、精度域错配、损失篡改及非法数字的直接反证；不能只把旧fixture设成更松。
3. 原B保留failed与全额连续GPU成本。独立CPU统计补全使用排他新目录、新协议和自己的源归档；
   训练/评估新增次数均0，不调用原attempt的run/finalize，不改其输出路径或伪造successful training。
4. 补全先核全部361原文件pins、93成员旧代码归档、六训练/三十评估完整身份与原failed成本；
   仅训练损失元数据校验使用明确有差异的修正源码。物理统计/官方配对/候选选择仍执行原冻结规则。
5. 派生表逐行同时绑定原forecast protocol与新statistics protocol，manifest说明每项来源。
   补全完成仅接受完整统计交付，不改原attempt状态，不冒称重做GPU、逐位训练或新的天气实验。
6. 补全从最早CPU入口计时，planned600/hard1200秒，禁网与原产物只读。软超继续、真实失败或
   硬截断保留新失败；该补全不能原地重试。UTC分组随后依独立协议核显式派生来源链。

## Consequences

**变容易的：** 数值审计与真实训练运算一致，可保留所有已完成计算而不浪费GPU；原失败与修正
后统计的身份和成本可以分别核对，避免把工程校验缺陷解释成天气结果。

**变难 / 代价（如实列出）：** 多一份独立协议、归档、来源manifest和CPU成本；未来引用必须说明
跨尝试统计来源，不能称原attempt成功。精度重构需覆盖逐运算舍入，不能据此推断所有浮点指标
均可放宽；B结果的两seed、冬季单区域和开发数据限制仍在。

**备选方案与否决理由：** 提高tables.close容差、删除损失断言、改原failed状态、重跑全部GPU或
复制部分有利分数均不采用。只记录失败并停止整个目标也不采用：原完整产物仍可合法资格核验，
独立C及原验收补齐继续，不把统计计划当实验进展。
