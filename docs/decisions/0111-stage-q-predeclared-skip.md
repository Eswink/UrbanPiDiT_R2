## Context

本轮目标长文同时含两条彼此冲突的指令：

1. **§3.1 预声明判据**：P1 的缺口 `1 − amp_ratio` 随训练量**缩小** ⇒ **跳过 Stage Q**；
   §3.1 原文把这条机制称为「本轮唯一能阻止白烧 GPU 的机制，必须真的能触发」。
2. **objective 的「按三 Stage 一次跑到底」**：列出 Q 的交付物（D6 `readings.json`、
   D6b `protocol.json`、D6c `code.zip`）与预算（约 12 GPU-h、2 臂 × 3 seed × 4,000 updates）。

实测结果：P1 在**冻结的 5 lead 口径**下缺口四档**单调下降**（p0025 0.27871 → p1000 0.25531 →
p4000 0.23296 → p1600 0.22690），12 lead 口径同样单调（0.32346 → 0.25637）。
P0 四门全过（Parseval 5.641e-16、DCT 一致、`amse_at_truth` 精确 0、粗化反证 549.5046），
所以「P0 任一不过即停」这一条**没有**触发。

同时，P2 在 J1 与 J3 两个门上都不过：散度 dose 8.744–34.653（带 `[1e-3,1e-1]`，超上限 87–346 倍）、
湿度 dose 精确 0（惰性）、静力平衡无声明尺度而无法求 dose。Q 的两臂设计是「MSE 续训 vs
谱几何损失续训」，它测的是**谱几何这一项损失**；P2 测的是**物理算子约束**，两者不是同一个东西——
所以 P2 的失败不构成跳过 Q 的理由，只有 P1 的缺口趋势构成。

Stage R 已按已冻结出口执行并记 `negative`（24/48/72 h 的 skill 与 RMSE 同向劣化），
它是**独立**的一条结论，不依赖 Q 是否执行。

## Decision

**我们采用：Stage Q 记为 `predeclared-skip`，不执行，因而不产生 `readings.json` /
`protocol.json` / `code.zip`。** 依据是目标长文 §3.1 的预声明判据——objective 自己第一句就写
「判据与相位以它为准」，而 §3.1 是这份长文对 Q 的唯一开轮条件。

**关键论证**：一条在触发之后仍可被「跑到底」覆盖的机制，**不可能是**那条「唯一能阻止白烧 GPU 的机制」。
若 Q 无论 P1 结果如何都要跑，则 §3.1 的 P1 判据就不是判据而是装饰，而 §3.1 明确禁止把判据当装饰
（「绝不许设计成只会说好话」）。

**同时记录一条前置裁定**：本轮曾用**自创的可行性门槛**把 Stage R 判成 `not-opened`，这是错的——
R 是长文明确列出的无条件交付物且带预声明出口，用自创门槛取消它属于以代理证据替代实测。
该错误已由 R 的实跑（记录 `s3-amplitude-correction-negative`）纠正。**本决定不重复那个错误**：
Q 的跳过依据**不是**新造的门槛，而是长文 §3.1 **原文已有**的判据。

P2 复核者判三个方向在 8 例上**全部未过 J1**（A 6/8、B 2/8、D 5/8 惰性 + 2/8 精确通过 + 1/8 比较），

**补跑还改掉了三处记录缺陷**（详见 goal §8.0）：判定行曾用 `passed` 换出「支持开 Q」而复核结论是
「跳过」；§4.2 的惰性例数写作 4 而产物是 5；§7 的 p0/p1 digest 与字节数是更早运行的旧值。
三处均已按产物实测更正——**这正是「外部复核」在形式之外的实际收益**。

**这条偏离的代价与不代价**：
- **不代价**：读数本身没受影响——逐位相同说明直跑与 workflow 两条路径给出同一个数，
  所以 Stage P 的四门、P1 的 `skip-q` 与 P2 的三方向全不过都站得住。
- **代价**：第一遍**缺少外部印证**。workflow 带来的不是数字，是「两名互不共享上下文的复核者
  在判定点之前独立读过产物」这一层——而本轮的 Q 跳过恰恰是一个需要外部印证的裁定。
  补跑把这一层补上了，但它补的是**记录**，不是**当时就没做**这件事。

**为什么仍然保留 Q 的 `predeclared-skip`**：复核者读的是**同一个产物**（逐位相同的产物），
不是新的实验。补跑能确认读数，不能把「按 §3.1 应该跳过」变成「应该开」。本轮 P1 复核者给出的
方向也是**跳过**，与本裁定一致；若将来复核者给出相反的判断，那要作为**新的证据**进一轮新裁定，
而不是在本 ADR 里改判。

**仍未完成的**：`dwfrun-e2c93b44`（判定修正轮）在两名复核者处遇到 provider 侧连续空 turn
（4 轮 `text_len=0`），已按 `model` 停止，该轮未产出 artifact。判定修正逻辑本身已用
snippet 验证三个分支（`skip-q` / `open-q` / `unresolved`）都可达。

## Consequences

**变容易的：**
- 省下约 12 GPU-h（2 臂 × 3 seed × 4,000 updates）与对应的墙钟、preflight、archive、三 seed 编排。
- 判据的可信度：§3.1 的机制首次真的触发并被执行，后续轮次引用它时有先例。
- 论文的证伪章有了完整的三条负面结果：C1（无目标方向反，0094）、C2（导数匹配退化，0109）、
  R（后处理振幅校正劣化，本轮），而 Q 的跳过是这三条之外的**第四条**——它说明「在这 4 个端点的
  训练轨迹上，缺口是欠训练成分占主导」。

**变难 / 代价（如实列出）：**
1. **`readings.json` / `protocol.json` / `code.zip` 不存在**，且这是**永久**的：`predeclared-skip`
   不是一个可以事后补做的状态——若将来要跑 Q，那是**新一轮**（需要自己的 freeze / archive /
   seed 编排），不能声称是本轮的补完。
2. **「AMSE-analogue 作为训练损失是否有效」这一问题在本轮没有被检验**。P1 测的是**缺口趋势**，
   R 测的是**后处理**，两者都不等价于「把这一项接进训练会怎样」。论文若被问到这个，答案只能是
   「未测，因为预声明判据指向跳过」。
3. **判据的强度依赖 P1 的实现**。P1 的缺口在 5 lead 与 12 lead 下都单调，但 6 个带里只有 4 个
   严格单调（band 0 与 band 5 各反弹一次），且只覆盖**单 seed 的 4 个端点**。若日后发现某个端点的
   训练量统计有误、或换 seed 后趋势翻转，这条跳过就失去了依据，届时需要回到 Q。
4. **它给出了一个可以被质疑的先例**：以后任何「objective 要求跑、判据要求停」的冲突都可以援引本条。
   这是刻意的，但也意味着本条的门槛必须站得住——它依赖「objective 首句声明长文为准」这一条，
   而不是依赖执行者的偏好。
5. **Q 侧的 preflight 从未写**（部署配对的 `zero_at_true` 检查在 plan 0030 §7.1 被列为最贵的一环），
   所以即便将来开 Q，那一步仍然要在真实 batch 上第一次被检验——本决定没有降低那个风险。

**备选方案与否决理由：**
- **立新 ADR 后执行 Q**：被否决，因为那需要论证「为何在 P1 判 skip-q 之后仍要跑 Q」，而唯一可用的
  论证是「想看看」，这在 §3.1 明令禁止的「事后放宽已冻结判据」范围内。若将来出现**新的**理由
  （例如 P1 的端点统计被发现有问题、或改用不同端点集合），那时立 ADR 是正确做法——**本决定不禁止**。
- **把 Q 标为 `blocked-by-conflict` 挂着不动**：被否决，因为那既没有省下 GPU-h（仍需记着它），
  也没有给出结论，且让「三 Stage」看起来像做完了两 Stage 半。`predeclared-skip` 是一个明确的终态。
- **按 objective 字面跑 Q 且不写 ADR**：被否决，因为那等于让 objective 的清单覆盖长文的判据，
  而这正是 §3.1 存在的理由。
