# 0101 — Stage E2（容量轴）：**不是缺授权，是已被 0048 永久关闭**；要开须先显式推翻那份出口

- **日期**：2026-11-08
- **状态**：proposed
- **范围**：目标长文 Stage E2「E2 容量轴须新 ADR 明确取代决策 0048 并取得用户具名授权，
  0048 无重开条款且其先例自我限制不得沿用」的**立项判定**。**不冻协议、不跑 GPU、0 读数。**
- **依据**：决策 **0048**（capacity axis scope and cap）、`docs/R7_S3_CAPACITY_WIDTH_RESULT.md`、
  `docs/R7_EVIDENCE_INDEX.jsonl` 的 `record:s3-capacity-width-result`、决策 **0057** §4.4

## Context

**① 目标长文对 E2 的要求，与 0048 的实际内容。** 目标长文写：
「E2 容量轴须新 ADR 明确取代决策 0048 并取得用户具名授权，**0048 无重开条款且其先例自我限制不得沿用**」。
这句话容易被读成「缺一份 ADR + 一句授权」。**实测不是**：0048 第 3 条是一条**binding 的失败条件**，
而那个条件**已经触发**。

**② 0048 第 3 条原文（`docs/decisions/0048-capacity-axis-scope-and-cap.md:55-58`）：**

> **封顶（binding，本决定最重要的一条）**：**宽度是最后一个容量臂**。若宽度臂也未能让 72h 三 seed
> 全正，则**整条容量轴（深度＋宽度）永久关闭**——此后**不得**再开任何容量臂：不得重试 `depth`、
> 不得再扫 `dim`、不得做宽＋深组合、不得以「再调一点容量」为名复活该支。

**③ 实测：宽度臂已跑完，出口未满足，故该条已触发。**
`docs/R7_S3_CAPACITY_WIDTH_RESULT.md` 标题即写明「72 h 三 seed 全负，按决策 0048 永久关闭整条
容量轴（深度＋宽度）」；索引 `record:s3-capacity-width-result` 的 `outcome_class` 为
**`negative`**、`candidate_state` 为 `not-candidate`。读数：

| 项 | 实测 |
| --- | --- |
| 72 h `interior_32` t2m skill（三 seed） | **−0.1658 / −0.2833 / −0.1418**（均值 −0.1970） |
| 预声明出口要求 | 72 h **三 seed 全正** ⇒ **未满足** |
| 6/12/24/48 h | 三 seed **全部更差**（Δrmse 均值 +0.2880 / +0.2751 / +0.0705 / +0.0419 K，0/3 更优） |
| 工程完备性 | 三 seed 均到 `total_updates=2400`、cohort 逐字相符、`width_expansion` 断言全过 |

⇒ 这不是「宽度臂没做」或「做得不好」，而是**它做完了、按预声明失败了**，而 0048 事先把
「它失败」定义为**整条容量轴永久关闭**。

**④ 所以 E2 的真实状态比目标长文的措辞更严格。** 目标长文说「须新 ADR 取代 0048 + 具名授权」——
两者**都必要但不充分**。真正要先做的是：**明确推翻一条已 accepted 决策的 binding 失败条件**，
并说明为什么该条件当初写得不对。仅「取代 + 授权」而不处理「这条封顶已经触发」，
等于**事后放宽已冻结判据**，与 `AGENTS.md` 明禁的形态同族（0048 第 3 条自己也写了
「不得以『再调一点容量』为名复活该支」）。

**⑤ 没有具名授权，所以本条不能越过这一点。** 目标长文把「用户具名授权」写成 E2 的前置；
本次会话**没有**收到任何具名授权（本文所有用户消息中都不含对容量轴的授权）。
按 Objective 的停止三条，「触授权边界」是**应当停下**的情形之一。

## Decision

1. **E2 本轮不立项、不开轮、0 GPU-h。** 理由按强度排序：
   - **（最强）** 0048 第 3 条是 **binding 的失败条件且已触发**——宽度臂已跑完并按预声明失败，
     该条把整条容量轴**永久关闭**，并逐项禁止「重试 depth / 再扫 dim / 宽＋深组合 /
     以『再调一点容量』复活」；
   - 目标长文要求的**用户具名授权没有取得**，且这不是我能自行给出的；
   - 即使两者都解决，也还缺一份**论证「0048 的封顶条件写错了什么」**的 ADR——
     「取代 0048」不等于「解释它为何失效」。

2. **不把 E2 记成「缺授权待批」这种轻描淡写。** 它是**已被关闭**，而不是**未被授权**。
   两者对后来者的含义完全不同：前者需要一个理由推翻一条 accepted 决策，
   后者只需要一个签名。

3. **若用户将来要求推进 E2，唯一的可执行前置顺序**（缺一不开）：
   - **(i)** 具名授权（用户书面指明「要重开容量轴」）；
   - **(ii)** 一份 ADR **显式 supersede 0048**，且必须回答「宽度臂的 negative 结论为何
     不适用于你想试的那个容量臂」——按 0057 §4.4，这需要论证**不是同一族**，
     而不是「上次只跑了 2,400 updates」这类算力辩解（0057 已实测旧臂不欠训练）；
   - **(iii)** 该 ADR 必须同时处理 0048 第 4 条记录的**初始化混杂**：`dim` 192→256 时
     155 个张量里 **150 个形状变化**，注册父**装不进去**，宽度「没有逐位恒等扩张」，
     故「容量」必然与「初始化/优化轨迹」混杂，须在 brief 与读数里如实标注；
   - **(iv)** 成本按实测重算：参数量 192/4 = 3,286,037；**256/4 = 5,790,389（+76%）**；
     320/4 = 8,999,253（+174%）。

4. **不据本条宣称容量轴「应该」重开或「已被证明」无关。** 本条只记录**行政与判据状态**：
   0048 的封顶已触发、授权未取得。宽度臂的 negative 是**它自己那一轮**的结论，
   `docs/R7_S3_CAPACITY_WIDTH_RESULT.md` 已写明不得外推。

## Consequences

**负面后果（代价，必须如实列出）**

1. **E2 在目标长文里是 Stage E 的一项，而本轮它是"被既有决策封死"，不是"待办"。**
   这意味着目标长文的 E 段有一条**结构上无法由执行者推进**：它需要用户既授权、又同意
   推翻一条 accepted 决策的 binding 条件。这不是我拖延，是判据如此。
2. **我必须承认一个措辞风险**：目标长文说「0048 无重开条款」，而 0048 其实**有一条**——
   第 3 条的封顶本身就是「不得再开」的条款。两种读法差别很大：前者暗示「没规定所以可以谈」，
   后者是「明确禁止且条件已触发」。本条按后者处理，并**不改目标长文**（它是不可变记录），
   由本条承担更正。
3. **若用户授权推进，成本与混杂都会被低估的风险仍在。** 0048 第 4、5 条已经记下
   「宽度没有逐位恒等扩张」与「H-D 不是更省成本（+76%）」，但**没有**测过 320/4 的
   训练稳定性；任何重开都要重新承担这两条未知。
4. **本条零读数，因此不能作为任何关于容量的证据。** 它连否决都不是——宽度臂的否决是
   2026-10-14 那轮做的，本条只是**读出并落实**了那份记录的行政后果。

**正面后果**：把 E2 从「缺一个签名」纠正为「需要先推翻一条已触发的 binding 封顶」，
避免以后有人拿「那就写份 ADR 取代 0048 吧」当作充分条件而实际在事后放宽判据；
把 0048 第 3/4/5 条的三项既有约束（封顶、初始化混杂、+76% 成本）在**同一处**列出，
使任何未来的 E2 提案必须逐条回应；明确记录**具名授权未取得**这一事实，而不是含糊带过。

**否决**：

- **把 E2 记为「待用户授权」就算处理完。** 否决：那会掩盖 0048 封顶已触发这一更强的约束。
- **本轮先写一份 supersede 0048 的 ADR 备用。** 否决：没有授权就写「取代」，等于替用户
  预设一个他还没做的决定；且没有「宽度 negative 为何不适用」的论证，那份 ADR 会是空壳。
- **以「宽度臂只跑了 2,400 updates」为由重开。** 否决：0057 已实测旧臂不欠训练；
  这正是 0048 第 3 条点名禁止的「以『再调一点容量』为名复活」。
- **顺手改 `model/**` 准备容量臂。** 否决：会改 `model_code_sha256`，
  使在跑的 `attempt06`（钉 `59340710…`）身份失效。

## 未决（须用户决定，不是我能定的）

- 若授权，用哪个容量臂、依据什么论证它「不是同一族」于已关闭的宽度臂。
- 是否接受 `dim` 变化必然带来的初始化混杂（0048 第 4 条），以及如何在读数里标注它。
