# 0029 实验常设下放与时长契约

- **日期**：2026-10-02
- **状态**：accepted

## Context

决策 `0021-experiment-authorization-channel.md` 将实验授权通道固定为执行前逐次
`AskUserQuestion`，或用户预先书面交付具名范围。它曾否决「代理自行决定有界实验」，理由是预算与
数据边界属于用户，不能由代理自行扩大。用户于 2026-10-02 明确选择「实验类动作全下放」、
「不设总上限」和「软预算 + 宽松硬上限」，主动推翻上述对本地实验与时长预算自主决定的否决理由；
数据、付费资源与破坏性操作边界仍归用户。书面授权与施工范围见
`docs/plans/0010-experiment-delegation-and-time-contract.md` §0/§3。

本决策取代 0021 的逐次实验询问及每次范围/预算不得自行扩展的限制，不取代「授权不豁免 R-006、
R-028 与诚实性判据」的纪律。M3 曾因截止只覆盖 GPU 阶段而留下 CPU 前置时间缺口，整轮
1805.1086s 超过历史「≤30 min」文字 5.1086s；此事实与 `budget_limited` 终态保留，不回溯修饰。

## Decision

1. **常设下放。** 本地 GPU 运行、训练/评估、触发实验 workflow，以及每次实验的时长与预算分配，
   由执行者在 R-006/R-028/R-054 与项目边界内自主决定，不再逐次 `AskUserQuestion`。
   本地资源内的训练规模也在下放范围内；已决定的范围、预算端点、产物与证据、失败/skip 处理
   必须写入该轮长文与运行协议，仍遵守「写下来之后再开始」（`bounded-study-run` 前置条件）。
   workflow 标签只表达触发意图，不构成授权；执行许可来自本决策而非标签。
2. **保留逐次授权项。** GPU 租赁与付费资源、多年度或新数据下载、数据发布 `--write`、`main` 合并、
   force push 与破坏性数据操作仍按原边界逐次取得显式授权。本决策不改变这些边界，也不豁免
   禁止 force push 的项目契约或 main 合并的 hook 限制；独占 GPU 仍按决策 0026 取具名授权，
   不因此获准干预邻居。
3. **时长契约。** 每次后续实验在训练前冻结的 `protocol.json` 中声明 `planned_seconds`（软预算）
   与 `hard_cap_seconds`（宽松硬上限，默认约为计划的 2 倍，具体数字在该轮长文写死）。
   两者均按**整轮墙钟**计，包含 CPU 前置、训练、评估、进程启动/间隔与清理，不能只约束 GPU 阶段。
   超软预算不中止，继续等待并记录 `soft_overrun_seconds`；仅硬上限因时长截断，终态记
   `budget_limited`/`failed`，已发生的 GPU 消耗全额记账，不算科学通过。真实错误、身份/资源门禁与
   冻结停止条件仍可提前停止，不能以软预算语义掩盖失败。承载实验的 workflow `timeout-minutes`
   必须高于该实验硬上限（秒数换算后严格比较），留出内部截断与证据收尾时间；允许按新实验提高
   数值而不是删除时限，无新增实验时不批量改现有数值。
4. **账本降为记账。** Campaign 不再设总 GPU-h 上限，账本是记账而非预算闸门。
   `cap_gpu_h`/`used_gpu_h`/`remaining_gpu_h` 保留为会计字段，C-02 的逐行求和与
   `cap_gpu_h - used_gpu_h = remaining_gpu_h` 算术不变；24.0 仅为历史会计基数，不是执行额度。
   state 块追加 `"budget_mode": "accounting-only"`；余量即使耗尽或为负也不单独触发停止。
   每行仍须记录实际消耗和证据指针，失败全额记账。「需新判据」「不可分辨或不能归因」及
   「需付费资源、新数据、main 合并或破坏性操作」等其余停止条件不变。
5. **不可豁免与不回溯。** R-006（先冻结协议）、R-028（离线禁网）、R-054（共驻、只读余量门槛且
   禁止对非本实验进程发信号）、R-009（不弱化测试/判据与诚实报告）、原始数据与归档只读、
   禁止合成回退、身份校验（`model_code_sha256`、source SHA256、`BUILD_COMPLETE`）、
   `scientific_claim: false` 与 limitations 如实记录均保持。
   `skip`/`cancelled`/`queued`/`partial`/`failed` 不算通过；节点推进与目标完成判定仍只由用户或
   独立复核裁定，执行者只可提议。本决策只对之后的实验生效，不修改冻结协议常量
   （包括 `global_deadline_seconds=1800.0`、`max_round_seconds=1800`）、历史「≤30 min」文字、
   M3 的 `budget_limited` 终态、冻结证据页或归档产物。

## Consequences

**变容易的：** 不再有逐次询问往返与授权欠账；执行者可以在本地资源内预先规划范围和时间，长实验
可在软预算之后继续跑到自然终点，而不为满足计划时长截断有效的训练/评估。

**变难 / 代价（如实列出）：** 总预算不再封顶，只剩单次硬上限约束，GPU-h 消耗可能超过原 24 上限
节奏。执行者须在每轮把 planned/hard 两个数字写进协议，写不清就没有可比对的软预算。用户不再逐次
看到实验内容，事后审计依赖长文、协议、运行记录与逐行账本。未来新增实验可能需要提高 CI 时限并
为失败收尾留余量；本轮不改检查器或执行代码，不声称新时长语义已由所有历史 runner 自动支持。

**备选方案与否决理由：** 保留逐次询问被用户明确否决。完全去掉硬上限不采用，卡死可能无限占用
资源。修改冻结常量以实现新语义不采用，会破坏归档重放与历史预算审计。把 workflow 标签当授权
仍不采用，它不能表达范围、软/硬端点与失败处理。
