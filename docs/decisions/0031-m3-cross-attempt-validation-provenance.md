# 0031 M3 缺项补测采用独立协议与逐文件跨尝试来源

- **日期**：2026-10-02
- **状态**：accepted

## Context

M3原一次尝试在1800秒GPU阶段截止后failed/budget_limited，已有六个完成400更新的selected checkpoint及七项验证，但缺23项、完整配对和成本表。原接受器只接受原目录36个成功receipt且连续GPU时长≤原1800秒，不能把补测写回原目录、修改原失败或把新的时长塞进旧协议。用户当前目标要求优先合法复用，不无故重训，决策0030允许执行者自定新的补测协议和输出，但明确不豁免旧科学停止线与身份校验。

## Decision

1. 本轮采用独立 `r7-m3-validation-complement-protocol-v1` 与全新排他输出、0训练更新，只对原确实缺失的23项val做新进程评估；1800软/3600硬按新节点长文冻结。原协议、1800常量、原attempt、旧证据页与全部归档文件保持只读，不调用原finalizer冒充原实验成功。
2. 每个补测进程在安全提取的原code.zip根执行原评估实现，逐文件/模型digest与原source/data/BUILD_COMPLETE/sidecar/训练签名强核；新驱动只编排时长、输出和计量，不改旧加载逻辑或生成一个伪造迁移的原protocol。
3. 新聚合逐文件引用六旧训练、七旧评估、23新补测及其receipt/artifact SHA256、采集/代码/协议身份与成本来源。原训练协议与新调度协议分别记录；同seed两臂比较，不把不同seed当配对。指标与案例仍按原完整17变量×五lead/528案例/510RMSE条件接受，不降低完整集合门。
4. 成本保留原失败全额连续GPU区间与整轮1805.1085775829852秒，并另列新补测的连续GPU区间、CPU前置、启动/间隔、评估及聚合清理的实际整轮时长。前置至最后reap的执行快照不冒称包含随后聚合；最终attempt/整轮成本回执才给最终whole与soft overrun。旧训练参数/FLOPs或峰值是引用旧实测，不能标成新计量或替代未知评估峰值。
5. 完整覆盖不等于原attempt成功，也不等于forecast改善或可推进。新聚合沿用原#60比较器与 `descriptive_outcome`：any unresolved暂停、不推进；普通授权不取消该冻结出口。N3/N4/N5仍需实际前置与出口齐备，不因希望关闭issue而弱化科学或工程要求。

## Consequences

**变容易的：** 可在不重训、不改历史失败的情况下补齐缺项，使每个数字及全部成本有来源，并保留可反驳的相同指标/案例/seed比较。

**变难 / 代价（如实列出）：** 多一份独立协议、驱动源码归档、逐文件来源manifest和整轮成本回执；聚合必须同时核两类协议和三个来源，存在身份/路径漂移、重复计费或阶段时长误标风险。跨尝试观测不宣称GPU逐位可复现，共驻负载可能改变墙钟；补齐后冻结暂停线仍可能阻断全部后续任务，不能拿工程通过覆盖它。

**备选方案与否决理由：** 修改旧1800秒协议或把旧failed改success违反冻结纪律，否决。直接重训六臂增加不必要成本并改变量，优先不采用；只有身份不能合法复用且另立新预注册方案时再考虑。使用当前代码绕模型digest或弱化配对/覆盖条件，否决。自改旧unresolved为不暂停以实现全部关闭，否决。
