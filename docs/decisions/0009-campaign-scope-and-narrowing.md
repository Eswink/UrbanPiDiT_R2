## D-1 不修 `eps=1e-6` 归一化 floor，先测量它的实际影响

**决定**：在 S3 预诊断阶段**不**改建 store 的归一化，而是先量化 floor 对两个水汽
proxy 的影响，并查明它能影响哪条路径。

**理由**：修归一化意味着**新 store、新 `data_identity`**，会让 B2/B3/C1/C2/C3 的
全部 checkpoint 被身份检查拒绝（即全部作废）。预诊断证明该缺陷**只能削弱辅助损失**，
**不能**污染前向状态（`forecast_inputs` 不转发 `process_targets`），
所以在打开辅助权重之前它不是阻断项。

**放弃的选项与代价**：
- 立即修归一化并重训一切：代价是作废 5 条已冻结实验链（≈2.3 GPU-h 训练 + 全部评估），
  换来的收益在本轮无法验证（辅助权重在 C1 里并未显示正向效果）。
- **代价（如实记录）**：C1 的 `aux>0` 臂在一个 2/8 通道近乎常量的目标上训练，
  这是该臂结果的既有局限，已在该文档写明。

## D-2 产物上限 16 GiB 越界 → 用「证据保全式剪枝」收窄，不删证据

**决定**：C1+C2+C3 未剪枝共写 5.758 GiB，使累计达到 **16.03 / 16 GiB**（越界）。
按授权「缩范围解决」，执行 `tools/prune_r7_run_checkpoints.py`：只删除每臂
`training_report.json` 记录的 `selected_checkpoint` **之外**的中间 checkpoint。

**理由**：授权给出的越界解法是**缩小范围**。剪枝保留全部评估目录、`rmse.csv`、
报告、协议与结果 JSON，且**保留**每个已发布数字所依赖的 selected endpoint
（其 SHA256 已在结果文件里），因此已发布数值仍可复现。

**放弃的选项与代价**：
- 停止 C2/C3：会让 #65 的三条消融轴只完成一条，直接损害判据完整性。
- 删除整个无效 C3 运行：会销毁那次 harness 缺陷的**实物证据**。故特意保留
  （0.945 GiB，pruner 的 fail-closed 检查也拒绝剪它）。
- **代价**：中间 checkpoint 不再可得，因此「从中间点重启训练」在 C1–C3 上不可能；
  每个被剪目录留有 `checkpoint_prune_receipt.json`（path/bytes/sha256）使删除可审计。

## D-3 #66 标 BLOCKED 而不训练停止器

**决定**：不启动自适应推理，不训练新控制器，不改 `model/r7_halting.py`。

**理由**：#66 的门槛是「固定深度模型已形成**有用的**精度—成本取舍」。实测：
最优 K 的排序只在 6h 跨 seed 一致，而 6h 的最优 K **就是最贵的 K=4**（收益 0.00%）；
12/24/48/72h 排序跨 seed 不稳定。同时**固定训练的 K=1 已经便宜 27.9%**，
所以任何自适应策略的上界是「匹配固定 K=1 再减控制器开销」——没有可改进空间。

**放弃的选项与代价**：
- 训练 gain controller 并调阈值：这会产出数字，但门槛不成立时那些数字只能证明
  「控制器能学会复现固定深度」，属于 #66 明文禁止的「加大控制器复杂度」。
- **代价**：oracle（用未来真值）显示逐样本最优 K 确实变化（+6.9~+13.0%），
  这个头寸**未被利用**；已如实记为**不可部署**的上界。

## D-4 #67 封存 test 报告标 BLOCKED（数据范围），不做重切重训

**决定**：不在本轮重切 held-out 并重训全臂以产出 test 数字。

**理由**：冻结的 B2 段把 test 全切在 **2 月**，而 train-only 气候态桶只有 **1 月**，
`evaluate_local` 因 D-3 设计（skill 必须与预测同 case）**无条件**计算气候态，
于是**任何臂**都无法在这段 test 上评估。重切会产生新 `data_identity`，
使全部现有 checkpoint 被正确拒绝 ⇒ **必须重训所有臂**。重训结果是**新实验**，
不能用来确认已冻结的 B2/C1/C2/C3 链；把它当作 #67 的封存交付会造成
「用新实验冒充旧链确认」的误导。

**放弃的选项与代价**：
- 重切 + 全臂重训（约 1.1 GPU-h 训练 + 全部评估）：可选但见上，且本轮预算内
  它只能作为**新实验**报告；未做。
- 放宽读者的缺桶拒绝：**禁止**（会把 held-out 数据泄漏进基线）。
- **代价**：test 数字**目前不存在**；`test` 仍是**未读**状态（执行在写出任何
  `rmse.csv` 之前失败，0 个指标文件），所以将来补做仍是「首次看测试」。

## D-5 #68 保持「地址约束」边界，不宣称更强的防护

**决定**：`http_pinned.py` 提供**连接地址约束**（非公网地址永不被拨号），
文档明确它**不**提供 allowlist、不检查响应内容、也不保证公网 origin 的性质。

**理由**：可以离线证明的是「被校验的地址就是被连接的地址」和「非公网地址被拒」；
无法证明的是「公网 origin 本身可信」。把后者写成前者就是夸大安全声明。

**放弃的选项与代价**：
- 加 allowlist：会把「固定官方来源已经足够」变成对任意 URL 的通用代理实现，
  与 #68 计划第 1 条「不必要地实现通用代理」相抵触；未做。
- **代价**：一个解析到公网地址的恶意 origin 仍会被正常连接；这是已声明的边界。

## D-6 默认策略不改（C2 的 mixed 结果不作为改默认真依据）

**决定**：`use_forecast_feedback=True`、`spatial_solver_feedback=False` **保持不变**。

**理由**：`solver_on` 一致变差（85 格里 28 worsened），但 `fb_off`（唯一略正面的改动）
同时**省 10.7% FLOPs**，所以它更像效率观察而非结构结论；#65 C2 明文要求
「保留当前默认直到通过新协议」，而本轮**没有**为改默认真建立新协议。

**放弃的选项与代价**：把 `use_forecast_feedback` 改为 False 省 10.7% 计算——
但当前数据（单季节、3 seed、800 步）不足以支撑改默认，且会与 B2/B3/C1 的既有配置
产生不一致。**代价**：保留了一个可能更贵的默认，直到有新协议。
