# 0027 N1 成本审计的共驻验收与历史身份读取例外

- **日期**：2026-10-02
- **状态**：accepted

## Context

N1 v2 成本补测已按执行前具名授权完成一次 P1 和原六 checkpoint × 五 val 时效的 30 次评估，
实耗 0.12826335332563354 GPU-h，四张终态成本表及 audit 登记已有证据。工程实现、零 allocator
基线与精确重放契约均有实跑核验；原 48/72h `cannot-distinguish`、N1 paused 与 N2d 仅提议未变。

当前会话重复的旧 objective 仍写「一卡独占」及「不读 test」，而历史执行使用准备期已明确授权的
shared-headroom 共驻政策（决策 0026）。另一次历史独立身份校验展开原 code.zip 全 953 成员并
读取 git blobs，包含无关的 `data/manifests/real_smoke/test.jsonl` 字节。这是历史 UCI 真实单站
工程 smoke 清单，不是本轮 ERA5 M2 封存 test；不能把读取事实改写成「所有 test 清单从未读取」。

两项验收边界经 AskUserQuestion 询问后曾未收到答复，等待记录保留。用户现直接回复：

> 均显示授权，并且允许下方决策权给你，所有实验均可安排

这是对已呈现两项裁定的真实后续授权及决策权下放，不是自动继续通知、未答回包或代理推定。
用户未逐字选择选项；下列具体选择由执行者在其授权下作出，并如实区分授权与执行者裁定。

## Decision

1. **本次按已授权的共驻修订版验收。** 采用决策 0026 与修复长文已经冻结的 shared-headroom：
   启动及每次子进程 spawn 前只读核 UUID 和余量 ≥2048 MiB；邻居 PID 只记录、不发送任何信号。
   不把历史执行冒称独占，也不追加一次独占重跑来满足已被本次裁定取代的旧设备措辞。
2. **仅接受已经发生的 smoke 清单身份读取为本次历史审计例外。** 例外对象仅为原 code.zip/git
   逐字节身份比较中 `data/manifests/real_smoke/test.jsonl` 的字节读取，目的仅为归档身份核对。
   保留原读取事实、原 checker 和回执；不声称读取发生前已获本例外授权。没有发现 M2 封存 test
   用于 N1 评估或科学选择的证据，但没有完整历史 syscall trace，不能给出任意进程从未读取的证明。
   该例外不授权新的 smoke 或 M2 test 读取、test 解码、评估、选择或训练。
3. **接受用户下放的实验安排与工程裁定权，沿用可核查边界。** 本轮的具名落点是
   `n1-evaluation-cost-supplement-v2` 的成本审计验收与上述两项裁定；执行者选择复用现有证据，
   不重复已完成实验。后续合规实验可以安排，但实际执行仍须按决策 0021/0025 在协议与运行记录中
   写清具名范围、预算、产物及失败停止规则，并满足主计划节点门禁、账本上限和共驻约束。
   总括安排权不豁免真实数据发布、零基线、精确重放、冻结科学判据或科研停止条件。
4. **不自动推进 campaign，也不宣告目标完成。** N1 保持 paused/current_node=N1，N2d 仅提议；
   不改写原 `cannot-distinguish`。本次新增 GPU-h 为 0，既有 v2 全额费用与账本不变。无新训练、
   臂/seed、下载、租 GPU、main/force/合并、issue 关闭或邻居信号操作。
5. **只追加独立的裁定记录。** 新回执为
   `outputs/r7_n1_cost_v2_acceptance_resolution_20261002/acceptance_resolution.json`；E-222、
   决策索引、CHANGELOG 与目标/主计划进度同步。原 v1/v2 运行目录、原授权、失败记录、冻结证据页、
   证据索引与旧的未答等待回执均不覆盖。两项边界不再等待用户选择，但最终目标状态由用户或独立目标判定。

## Consequences

**变容易的：** 旧设备措辞与历史实际授权的矛盾有一个具名验收口径；历史清单读取有明确且狭窄的
审计例外，不必消耗 GPU 去重跑已经齐套的成本证据，也无需反复向用户询问相同裁定。

**变难 / 代价（如实列出）：** 读者必须区分原执行授权、后来验收裁定及未来实验安排，不能把本例外
误当通用 test 读取许可。原历史 checker 的泛化「未读 test」表述仍需连同补充限制阅读，不能撤销
读取或提供缺失的 syscall trace；共驻查询仍不预留显存，且本轮没有邻居负载性能证明。
治理新增文本与既有精确 CI SHA 分开报告，未提交或未跑新 CI 的内容不能冒称被历史 CI 覆盖。

**备选方案与否决理由：** 保留旧独占措辞并重新跑 GPU 会重复已授权的成本工作，不改善科学证据，
故不采用。隐藏历史读取、改旧回执或过滤旧 checker 后冒称原 8592 项合规均会破坏可追溯性，故不采用。
将身份例外扩展到 M2 test 或自动进入下一节点会超出本次验收所需并违反冻结边界，故不采用。
