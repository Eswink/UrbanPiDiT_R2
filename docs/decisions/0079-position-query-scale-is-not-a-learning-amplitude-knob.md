# 0079 — 0078 的 §④「用 `scale` 修正学习幅度」前提**实测不成立**：`scale` 只放大前向敏感度、不放大学习幅度；R4 的执行设计必须改问法（两臂初始化路线仍未定）

- **日期**：2026-11-03
- **状态**：accepted
- **范围**：`docs/decisions/0078-position-retention-reeval-admission.md` §Context ④ 与
  §Decision 2 的「`scale` 修正操纵强度」论证；R4（位置保留 H-B）的**开轮准入仍然有效**，
  但它**据以开轮的那条因果解释被本 ADR 更正**。不改 0078 正文（历史文本不静默重写）
- **依据**：0078（被更正者）、`model/typed_evidence_r7.py:134` 与 `:241`、
  `training/r7_long_rollout_runner.py:385`（AdamW）、H-B 冻结 `protocol.json` 的 `recipe`
  （`lr 2e-5 / warmup 10 / updates 2400 / clip 1.0 / weight_decay 1e-4`）、
  本会话在 `/tmp/r4route/` 的六项 CPU 实测（零 GPU、零写入 `outputs/`）

## Context

**① 0078 §④ 的论证是什么。** 它把旧臂的 null 归因于「操纵强度不足」，并提出修法：
在打分上乘一个冻结常数 `scale`，使初始有效打分幅度与同层投影可比，取
`scale ∈ [1e3, 2e3]`（对应 `score_std` 0.5–1.0、归一化熵约 0.94）。该论证隐含一条**因果链**：

> `scale` 放大打分 ⇒ query 获得足够的「学习幅度」 ⇒ 优化器自发生成的 query 不再病态小。

本 ADR 实测的是这条链的**第二环**，结论是它**不成立**。

**② 实测事实一：`position_query` 初始化为**精确零**。**
`model/typed_evidence_r7.py:134` 是 `nn.Parameter(torch.zeros(dim))`。用 H-B 冻结协议里的
真实构造参数（`dim 192`、`patch_size 2`、真实 `channels`/`denorm_*`/`field_*`）实例化
`TypedEvidenceRouter`，seed 41/42/43/7 四个种子实测 `‖position_query‖` **全为 0.0**（148,992 参数）。
⇒ 任何 typed 轮**在 step 0 都精确等于 pooled 臂**；query 必须**学**出来才可能不同。
这一条对 `scale` 的推论是决定性的：**`scale` 乘在一个零向量上仍是零**，
故 `scale` 在初始化时刻**不产生任何打分 spread**，它的全部作用都发生在 query 已非零之后。

**③ 实测事实二：`scale` 是**前向敏感度**旋钮，不是**学习幅度**旋钮——AdamW 把梯度整体缩放约掉了。**
R4 要沿用的配方是 `torch.optim.AdamW(lr=2e-5, weight_decay=1e-4)`（`r7_long_rollout_runner.py:385`
实测），2400 updates、`clip 1.0`。AdamW 的每坐标步长 ≈ `lr · m̂/√v̂` 与梯度**幅度**无关。
把整套 loss 乘 `c²`（等价于把所有梯度乘 `c²`，即模拟「打分放大 c 倍 ⇒ 梯度放大 c 倍」），
在**真实超参**下跑 1200 / 2400 步：

| 步数 | `‖q‖`（mult=1） | `‖q‖`（mult=1e6） | `max‖Δq‖` | 逐位相同 |
| ---: | ---: | ---: | ---: | --- |
| 600 | 0.167292207 | 0.167292327 | 7.898e-07 | 否（float32 噪声） |
| 1200 | 0.336266577 | 0.336266756 | 1.077e-06 | 否（float32 噪声） |
| 2400 | 0.676645219 | 0.676645517 | 1.259e-06 | 否（float32 噪声） |

**十个数量级**的梯度缩放给出**相对差 `2.8e-6`** 的同一条轨迹。加 `clip_grad_norm_(1.0)`
的复核（评审最可能提的反驳）同样通过：两种缩放都落在 clip 之上、方向一致、被归一到单位范数，
`max‖Δq‖ = 9.686e-08`（相对 `2.8e-6`）——**clip 不破坏这个不变性**。

⇒ 因此 0078 §④ 的「把 `scale` 提到 1e3 让 query 学到足够幅度」**在 AdamW 下没有作用机制**：
`scale` 会让**给定的** `|q|` 产生更大 spread（这是真的、也是它唯一的作用），
但它**不会让 `|q|` 长得更大**。两者是不同的量，0078 §④ 把它们合成了一个因果链。

**④ 实测事实三：H-B 的 `|q|` 小，是**梯度方向近似无信号**（随机游走），不是 lr 饿死。**
用同一套真实超参给出两个反事实上界（每坐标步长 ≈ `lr`）：

| 口径 | 值 | 与三个已登记 `|q|` 的关系 |
| --- | ---: | --- |
| 每次更新位移 `lr·√dim` | 2.771281e-04 | — |
| 相干上界 `lr·√dim·N` | 0.665108 | 三个实测值只到其 **1.11% / 1.87% / 1.26%** |
| 随机游走期望 `lr·√dim·√N` | 0.013576 | 三个实测值是其 **0.545 / 0.918 / 0.619**（均值 **0.694**） |

⇒ 已训练的 `|q|` 落在**随机游走尺度**上（0.69× 期望），距相干上界差两个数量级。
这只由「每步方向近似不相关（梯度信噪比极低）」产生，**不能**由「lr 太小」产生——
lr 若再大 100 倍，随机游走尺度也只涨 100 倍，而上表显示它已在该尺度上。
**故正确的问题是「为什么位置加权拿不到有方向的梯度」，而不是「如何把幅度调大」。**

**⑤ 与网格的关系（与 0078 §③ 一致，不变）。** 打分定义在 P 个 patch 位置上，
P 只影响熵对给定 `score_std` 的映射，不影响「`scale` 不改变学习幅度」这条。
实测（`P=1089`、`dim=192`、20 万次抽样）：归一化熵到 0.99/0.94/0.90 分别需要
`score_std ≈ 0.3742 / 0.9174 / 1.1860`；这比 0078 用的小 `σ` 展开（`1 − σ²/2`）**严格更松**——
实测 `σ=0.5` 时 `H=0.9821`（展开给 0.875），`σ=0.874` 时 `H=0.9455`（展开给 0.618）。
⇒ 0078 的 `[1e3, 2e3]`（`score_std` 0.5–1.0）**在熵口径下仍落在可行区内**，
但其中「约 0.94 熵」那一行是**用错公式算的**（真实 0.94 需 `score_std≈0.92`，
不是 0.5–1.0 的中点附近）。可行区不变，理由换成本表的实测值。

## Decision

1. **保留 R4 开轮**（0078 §Decision 1 不撤），但**更正其因果解释**：
   R4 测的不再是「把学习幅度提上去之后位置加权是否有效」，而是
   **「在给定的前向敏感度下，位置加权是否改变长 lead 读数」**。
   `scale` 的角色被重新定义为**前向敏感度旋钮**，它在本题里**不承担**「修正优化器病态」的职责。
2. **`scale` 的定值与判据按实测重述**（替换 0078 §Decision 2 的「熵约 0.94 对应 1e3」）：
   - `scale` 仍由**跑前**只读前置在真实 val 批次上量出并写死，**不扫、不看读数后调**；
   - 跑前判据用**实测映射**：归一化熵目标 `[0.90, 0.99]` 对应 `score_std ∈ [0.374, 1.186]`
     （`P=1089`）；`熵 < 0.5` 仍视为退化成 one-hot、该轮读数**不得**用于判定原假设。
3. **必须在 brief 与冻结协议里如实写明的新 limitation**：
   「`scale` 只改变前向敏感度；由于 `position_query` 零初始化且 AdamW 对梯度整体缩放不变，
   本轮的 `scale` **不改变** query 能学到的幅度。因此本轮**不能**回答
   『优化器为何学不出有方向的位置权重』——那是一个**不同的**、本轮不问的问题。」
4. **两臂初始化路线（0078 §Context ⑥ 留下的）本 ADR 仍不拍板**，但把它的判据收紧：
   路线①（从 H-B 归档迁移 9 个张量）会把 H-B 的**训练后** query（`|q|≈0.008`，即③④里那个
   随机游走产物）带进新轮，于是「新轮从 pooled 处起步」不再成立；
   路线②（`isolated_stream()` 下新初始化）保持零起点，但引入一次新随机流。
   **这两条给出的不是同一道题**：①从旧轮训练终点续跑，②从 pooled 起点重跑。
   ⇒ **执行设计 ADR 必须先明确本轮问的是哪一个**，并在桥 (e) 里相应断言
   （①须断言迁移张量逐位等于归档 SHA；②须断言两臂 9 张量逐位相同且 `|q|==0`）。
5. **不撤 0078 的开轮准入**：它的核心事实（旧臂 null 是弱操纵下的 null、原页自证、
   该缺陷与网格无关）**不受本 ADR 影响**；被更正的只是「`scale` 如何修复它」这条机制解释。

## Consequences

**变容易的：**
- 在花任何 GPU 之前就排除了一个**会白跑的轮次设计**：若照 0078 §④ 的字面理解去跑，
  得到的读数会被误读成「幅度已修正，位置加权仍无效」，而实际只是同一个随机游走 query
  被放大了前向敏感度。该误读现在被提前挡住。
- 「为什么 query 学不动」被定位成一个**有明确量纲的诊断**（`|q|` vs `lr·√dim·√N` 的比值），
  后续任何关于位置加权的轮次都可以先算这个比值判断前提是否成立，成本为零。

**变难 / 代价（如实列出）：**
- **本 ADR 只否定一条机制解释，没有给出替代的修法。** 若目标是「让 query 学到有方向的幅度」，
  站得住的候选至少是「改初始化尺度让 query 一开始就非零」「改用对梯度幅度敏感的优化器」
  「用更大的 lr」——**三者都同时改了两个因子**（幅度与聚合方式），按 0057 都不能与 R4 合并，
  须各自另立 ADR。**本轮不采用其中任何一个**，故 R4 仍只能回答③定义的窄问题。
- **0078 的 `[1e3, 2e3]` 与「熵约 0.94」那一行是错配的**：数值区间仍可用，但理由必须换成
  §Context ⑤ 的实测映射。任何引用 0078 该表的人若不读本 ADR，会继续用错的熵-`score_std` 关系。
  这是选择「不静默重写历史文档」的代价。
- **零初始化这一事实本身是新的**：0078 起草时未记录 `position_query` 初值为 0，
  因此「旧臂 null = 弱操纵」这一读法现在要补一句——旧臂**起点精确等于 pooled**，
  其 `|q|≈0.008` 是 2400 步随机游走的产物。这不推翻 0078 的准入，但让它对 null 的
  表述更准确（也更强：连起点都是退化的）。
- **不产生任何关于「位置保留是否必要」的结论**：本 ADR 零 GPU、零新读数，
  它的全部内容是**对一条推理链的否证**，不得被引作任何实验证据。

**备选方案与否决理由：**
- **备选 A：把 0078 状态改为 `superseded by 0079`。** 否决：0078 的**决定**（开轮、七 gate、
  出口、成本）**仍然有效**，被更正的只是 §④ 的机制解释与 §Decision 2 的一个数值对应。
  整体取代会错误地作废仍然成立的准入记录，违反「取代链只为真实取代使用」。
- **备选 B：直接改 0078 正文。** 否决：违反「历史文档不静默重写」的既有先例
  （与 0077 对计划 0025、本会话对 `R7_S3_GLOBAL_MIXING_RESULT.md` 的处置一致）。
- **备选 C：据此否决 R4。** 否决：R4 的准入理由是**旧臂 null 为弱操纵下的 null**
  （0078 §Context ②，原页自证），这条**未被推翻**；§③④ 只说明「`scale` 不是修复它的正确工具」，
  不等于「问题不值得问」。**但必须把问法收窄到 §Decision 1 的表述**，否则就是明知机制不成立仍按原叙述开轮。
- **备选 D：把 `scale` 改成可学参数以「自动学到合适幅度」。** 否决：可学 `scale` 与可学 query
  完全冗余（两者只以乘积 `scale·q` 进入打分），徒增一个不可辨识的自由度；
  且它与 R4「唯一因子是聚合方式」的设计直接冲突。
