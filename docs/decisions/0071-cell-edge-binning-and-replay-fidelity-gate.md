## Context

### ① R-006 时序：**实测推翻「先下载后冻结」的说法**

此前的质疑来自 `protocol.json` 的 mtime（`2026-10-27 13:26:58 +0800` = `05:26:58Z`）
晚于 `download_receipt.json` 的 `downloaded_utc = 2026-10-27T05:13:48Z`。
但 mtime 只反映**最后一次写入**，不反映冻结何时首次成立。实测：

```
stat protocol.json  → mtime 13:26:58 +0800, birth 12:02:35 +0800 (= 04:02:35Z)
stat download_receipt.json → birth 13:13:48 +0800 (= 05:13:48Z)
```

协议文件的 **birth 早于下载 71 分钟**。更强的证据是摘要可重建：`_digest(body)` 是对
`json.dumps(body, sort_keys=True, separators=(",",":"))` 的 sha256
（`scripts/r7_urban_static_round.py:89-91`）。把当前 `protocol.json` 去掉 `protocol_sha256` 键、
从各层计划里去掉后加的 `epoch`/`year` 两键、并把 `frozen_utc` 置回 `2026-10-27T04:02:35+00:00`，
重算得：

```
c402867022c5dee3876fb597dfb0af3de26ecf167ec367d617aec6bb83708cef
```

**逐字符等于** `download_receipt.json` 里记录的 `protocol_sha256 = c4028670…`。
即下载当时所用的协议是**真实存在且可精确重建**的，其 `frozen_utc` 就是文件 birth 时刻。

⇒ **R-006（先冻协议再下载）在 acquisition 层面成立**。「协议冻在下载之后」是错的。

### ② 但确实存在一次**冻结后改写**（记录层面，非时序违反）

下载之后，聚合器需要 `epoch`/`year` 两个记账键，`freeze()` 被再次调用，`protocol.json`
被重写为今天看到的 `8cc3c673…` 版本（`frozen_utc` 也随之变为 `05:26:58Z`）。
`aggregate_receipt.json` 如实记了两个摘要（`protocol_sha256` 与
`protocol_sha256_at_download`）与一段 `protocol_amendment` 说明。这是**已披露的**，
不是隐瞒；但后果是：

- 发布 `manifest` 与 `static_identity` 绑的是**改写后**的 `8cc3c673…`；
- 「下载时冻结的那一版」只能靠上面①的重建方法证明，**仓库内没有单独留存其字节**。

⇒ 这是**可审计性缺陷**，等级低于时序违反，但**必须**在证据页写明重建方法与
`c4028670…` 的来历，否则读者无法自行验证①。

### ③ `frozen_before_any_download` 是**硬编码 `True`**，不检验事实

`scripts/r7_urban_static_round.py:210` 把 `"frozen_before_any_download": True` 直接写进 body，
`freeze()` 里**没有任何**「与已有下载回执比较时间」的逻辑。所以该字段是**声明**，
不是**测量**。它在 attempt01 恰为真（①已证），但**不能**作为任何一轮的证据——
这是记录缺陷，本轮顺带记明，不改该字段语义（改它属于代码变更，见 Decision 第 3 条）。

### ④ 格界语义缺陷（上一轮已双重确认，此处只列结论）

`urban_static_aggregate.py:114-115`、`:123-124` 按原生格心归属，而 `DATA_SPEC.md:37`、
模块常量、发布 manifest 均声明按**格界** `area_weighted_coarsen`。GHSL 3 arcsec 与 0.25°
目标网格半格错位（目标北界在第 `-7169.500035` 行、西界在第 `8259.500481` 列），
故两种规则系统性不同。执行者独立复算：模块函数全字段复现已发布值到 `5.91e-8 %`（证明现值为格心结果）；
精确面积重叠重算 11 个非零抽样格，中位差 `0.139%`、最大 `1.225%`。
「独立再派生核对」`scripts/r7_urban_static_round.py:433-436` 共用格心规则，
其 `5.15e-08` 只证明两条路径一致，**不构成语义正确性证据**。

### ⑤ 编排闸门在重放轮里**结构上不可能通过**（0070 实测）

`dwfrun-34a44d57` 三轮复核 `high=1 / 1 / 2`、`clean=false`，确定性快门通过，
于是按预声明规则停下：实跑 stage 0、`attempt02` 未创建、零下载、零磁盘消耗。
问题在于该闸门要求「代码干净」，而 0070 的重放轮**按设计不改任何文件**——
复核者必然持续发现**既有**缺陷。**判据与轮次性质不相容。**

## Decision

### 第 1 条：格界归属修复（新 ADR 授权，本轮执行）

1. 把 `_native_row_weights` / `_native_col_targets` 的归属改为**格界面积重叠**：
   每个原生格按「与目标格重叠的真实球面面积比例」把值分配到它触及的目标格
   （lat 用 sin 带比例、lon 用线性比例，二者相乘），而不是按格心所属格整体归属。
2. 该变更**必须**伴随：
   - `protocol.json` 重新冻结（新 `attempt` 目录），`frozen_utc` 为新时刻，
     `protocol_sha256` 随之改变；
   - `spatial_resampling` 语义与实现**一致**后才允许发布（发布前加一条断言：
     归属函数必须使用格界重叠，可用一个合成 2×2 原生格／1 个目标格的单测反证）；
   - **独立再派生核对**不得再共用归属 helper：抽样格必须用**第三套**实现
     （例如直接对原生格做 polygon 外接面积求和），否则 `recheck` 依旧无效——
     这是对⑤那类「共享错误前提」的正面修复。
3. 产物落**全新排他** `outputs/r7_urban_static_covariates_attempt03/`（`attempt02` 不存在，
   `new_attempt()` 会取 max+1，故实际编号以运行为准，不得手写）。
4. `attempt01` 的字节**不删不改**，其数值在证据页与账本中被明确标注为
   **「格心口径（与 DATA_SPEC 不符）」**保留，作为历史记录与本次修复的对照。
5. 预算沿用 0064（planned 21,600 s / hard 86,400 s、网络 ≤40 GiB、磁盘余量 ≥60 GiB）；
   若实测超 `planned_seconds` 另立更正决策，**不**就地改硬限。

### 第 2 条：编排闸门改判「重放忠实性」（本轮执行）

把草稿的合取条件从「复核者 `clean=true`」改为下列**可机械判定**的合取：

- **F1** 三个实现文件的 git blob 与**基线提交**逐字节相同
  （基线由本轮写死为 `7065f19`；若第 1 条改了聚合器，则基线改为**第 1 条落地后的新提交**，
  且必须在协议里明文记下该 SHA）；
- **F2** 六相位 `world.run` 退出码全 0；
- **F3** `published/manifest/BUILD_COMPLETE.json` 的 `build_complete` 为 `true`；
- **F4** `tools/r7_round.py verify` 退出码 0。

复核者**仍然运行**并**仍然报告**发现，但其 `clean` **不再**是闸门条件——
它的产出是「发现记录」，写进证据页，而不是阻断条件。理由：在重放轮里，
「代码有没有既有缺陷」由**基线是否相同**回答，不由复核者的主观汇总回答。
**放宽的边界必须写明**：这不是放弃复核，只是把「是否开跑」交给可机械判定的忠实性，
把「发现了什么」交给复核记录；任何**新引入**的缺陷仍由 F1 拦截（字节不同即停）。

### 第 3 条：`frozen_before_any_download` 不改语义，但必须标注

不改该字段的写入逻辑（那属于代码变更，不在本 ADR 的两个目标内）。
要求：证据页与协议 `limitations` 中**必须**写明「该字段是声明而非测量；
attempt01 的真实时序已由 0071 ①的摘要重建法独立证明」。
把该字段改成「与下载回执比较时间后得出」列为**下一轮的候选**，需自己的 ADR。

### 第 4 条：记录更正的落点

① 的结论**必须**写进：
- `docs/R7_URBAN_STATIC_COVARIATES.md`（attempt01 证据页）——但改它会变更其被账本 pin 的
  `evidence_sha256`，故**必须**同时更新账本行并保留 `evidence_revisions` 链；
- 本长文 §7（已在此前小节记了缺陷，现在补 R-006 的更正）。

## Consequences

**变容易的：**
- 聚合语义与 `DATA_SPEC` 一致；「按格界」这句话第一次变成**可被反证测试**的断言。
- 编排闸门可判定、可复现、与轮次性质相容；重放轮不再因既有缺陷被永久卡住。
- attempt01 的 R-006 质疑被摘要重建**证伪**，且重建方法写进文档，读者可自行复验。

**变难 / 代价（如实列出）：**
- **要重下约 14.5 GiB、再占约 20 GiB 磁盘**（`/data` 现余量 569 GiB）。这是理解代价，
  不是新增授权范围——仍受 0063/0064 的字节与时间门约束。
- **`static_identity` 必然改变**（聚合规范与输出字节都变）。出现「同名产物两个数值」的
  解释成本，靠「格心口径 / 格界口径」标注消解。
- **attempt01 的数值不再是「可用」的**：它是错误口径。虽然保留，但任何下游使用都必须
  换成重派生结果。若已有下游（当前自查无）消费了它，需要同步修正。
- **复核者的产出降级为记录**：这是刻意的取舍，代价是「既有缺陷」不再阻断开跑。
  为此 F1 必须严格——字节不同即停，防止实现被悄悄改动。
- **`frozen_before_any_download` 仍是声明**：本 ADR 只要求标注，不修机制，
  所以同类问题下次仍可能出现，直到第 3 条的候选落地。
