## 4. #65 预诊断（第一步，必须真的做）

#65 原文明确许可：「**对旧 checkpoint 的只读诊断可提前做**，但不得持续优化反复看过的那 8/24 个 validation 案例」。

必须逐项产出（CPU，零 GPU）：

1. **process proxy 的数值尺度审计**：逐个 proxy（尤其水汽类）记录真实 std、eps 截断比例、标准化后范围。**已知线索**：moisture_advection std 9.1e-9 → 被 1e-6 floor 压到 72.5%；moisture_convergence 1.7e-8 → 39.2%。**查明这是否使 process state 的水汽通道近乎常量**——若是，结构的信息输入是残缺的，这是**可修**原因而非"方法无用"。
2. **辅助梯度 vs 主梯度**：train-only 记录 forecast loss 与 process loss 对共享 encoder/reasoner/solver 的梯度范数与夹角（区分读出 head 与共享参数）。**"夹角负"不是因果证据**，只作诊断记录。
3. **K0–K4 轨迹**：同 model/data 签名下记录逐 K 的误差变化、修正范数、相邻修正 cosine（复用 #53 更新几何）；trace 可审计但**不得**因保存完整计算图破坏 streamed 内存优势。
4. **归因结论**：明确写出"两个负结果最可能的原因是 A/B/C"，并给出支持/反对证据。**若证据不足，如实写"不能区分"**，不编造归因。

## 5. 已知的方法学事实（避免重复踩坑）

- **同更新 ≠ 同算力**（B1 实测：四族 forward FLOPs 相差 1.46×）。任何 process vs generic 比较必须**同时给参数量/forward+bwd FLOPs/wall time/例数四张表**；B3 的 800 步未按容量调整，故"容量不足 vs 步数不足"**至今未决**——若做 B3 重跑，必须让算力随容量对齐并把该对照写进协议。
- **判据必须实验前冻结**，digest 机制已验证能抓事后改动（B2 抓到过作者自己）。不得事后增删 required cell。
- **#60 比较器是唯一口径**（seed 全键配对、缺项 fail closed、`gate_met` 只读冻结判据、大量 unresolved 不得因单项 improved 而假通过）。
- **climatology 在 t2m 上占优是本数据范围的产物**（1 月只有 4 个 (month,hour) 桶），**不是"基线很强"**；任何跨季节结论必须标注 UNVERIFIED，扩到多季节后应重述这一判断。
- **val/test 是工程再划分**，不是封存测试集（`test_read: false`）；**test 在整个 S3/S4 阶段不得用于选型**。
- **17 条实验 workflow 不触发**（tag-gated 设计）；ci.yml 自跑不等待不作门槛。
- 产出为负时**不得**靠加模块/phrase 掩盖；负结果是合法终态。
