# 外部信息来源与引用

本文件覆盖 R-049 – R-050：智能体如何取得本仓以外的公开信息，以及引用这些信息时的
可核查要求。与另外两组出网规则分工不同：R-016（`python-implementation.md`）管**代码**
在哪里联网；R-028（`ci-and-verification.md`）管**实验**必须真正禁网；本文件管**检索行为
与引用证据**。

## R-049 外部检索必须经网络检索员

- **级别**：必须
- **范围**：一切由智能体发起的外部信息获取（主链路与子智能体委派）
- **陈述**：需要本仓以外的公开信息（第三方库用法、版本变更、API 参考、论文、报错信息）时，
  必须委派 `web-researcher` 子智能体；主链路**不得**直接调用 `WebSearch`/`WebFetch`
  （由 PreToolUse 闸门 `guard_web_research_route.py` 拒绝）。该子智能体不可用
  （委派报错 / 超轮次 / 空返回）时，降级为主链路 `curl` 抓取，并在记录里写明降级原因。
  仓库内部的问题不属于本规则范围。
- **依据**：E-182（全仓扫描：`tools/`、`tests/`、`.github/`、`scripts/`、`training/`、
  `model/` 内 `WebSearch`/`WebFetch` **0 命中**——此前不存在任何门禁）、E-183
  （`.zcode/agents/` 两个定义的工具集：`planner.md:7-12` 也带 WebFetch/WebSearch，
  `web-researcher.md:7-9` 只有这两个）、E-186（工具事件的 hook 载荷没有子智能体身份字段）、
  E-187（子会话不跑 hook —— **推测**，未实测）
- **现状**：A 类 —— 引入后由 hook 强制；**引入前的历史检索行为未留痕，属「未测量」**，
  如实记录，不回溯判定
- **执行方式**：hook（`tools/agent_hooks/guard_web_research_route.py`，退出码 2）+
  能力（`.agents/skills/web-research/SKILL.md`）；`tools/check_conventions.py` 不判定
  （运行时行为，checker 无法观察）
- **例外**：无。`session_id` 以 `sess_subagent_` 开头时放行，是防止未来客户端开始给
  子会话跑 hook 时把 `web-researcher` 自己锁死的**防自锁机制**，不构成规则的例外
- **引入日期**：2026-09-28
- **复核触发**：客户端开始给子会话跑 hook、或工具事件载荷加入子智能体身份字段时，
  改为按身份放行；`web-researcher` 不可用成为常态时，重估强制路由是否仍值得

## R-050 外部引用必须可核查，失败必须如实记录

- **级别**：必须
- **范围**：写进仓库文档、报告与提交信息的外部结论（含 `web-researcher` 的返回）
- **陈述**：引用外部来源必须给出 URL 与访问日期；「可达 / 不可达」必须**先实测再写**；
  检索摘要、二手转述与子智能体输出一律**不构成证据**，关键数字必须回到一手来源逐条核对；
  不可访问的来源照记（URL + 失败原因），禁止用回忆、推断或「看起来合理」的搜索结果补全。
- **依据**：E-184（先例：`cn.bing.com` 的 WebFetch 搜索摘要「完全无关」，此后每条
  「可达」都以实测端点为准 —— `docs/R7_URBAN_EXTENSION_BLOCKED.md:37,39-41`；
  「搜索得到的每个数字都必须回到一手来源核对」与可用性清单 ——
  `docs/goals/open-issue-resolution.md:97-103`）、E-185（`docs/*.md` 共 26 行含 URL：
  14 行外部引用无访问日期、6 行本仓 CI run 链接、2 行 curl 命令模板）
- **现状**：A 类 —— 引入后成立；**历史 14 行外部引用无访问日期，本轮不回填**（见已知局限）
- **执行方式**：能力（`.agents/skills/web-research/SKILL.md`）+ 人工自觉
  （`check_conventions.py` 不可判定：抓取方式与失败原因不写在被检查的文件里）；
  抓取留痕由 PostToolUse 提示 hook `tools/agent_hooks/note_external_fetch.py` 辅助
- **例外**：无
- **引入日期**：2026-09-28
- **复核触发**：引用纪律被违反 ≥2 次时，考虑立仓库内引用台账
  （URL / 访问日期 / 抓取方式 / 回应 sha256）

### 已知局限（如实记录）

- 闸门只在本仓库、经 ZCode 生效；直接命令行与其它客户端不受约束。
  它是「防误用」而非**沙箱**——与 R-028 的免责说明同理。
- 闸门只覆盖主链路：工具事件的 hook 载荷没有子智能体身份字段（E-186），且当前构建下
  子会话很可能根本不创建 hook runner（E-187，**推测**）。因此 `web-researcher` 自己的
  检索行为不受该闸门约束——它本来就是被授权的出口。
- 历史引用欠账：14 行无访问日期的外部引用**保留原样**。回填等于用今天的日期冒充当时的
  访问记录，那比缺失更糟。规则只约束引入之后新增或修改的引用。
