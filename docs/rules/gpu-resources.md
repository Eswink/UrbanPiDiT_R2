# 本机 GPU 资源与共驻

本文件只规定设备占用政策，不规定科学接受阈值。按决策 0026/0029：本机共驻不变，实验与时长已常设下放。

## R-054 本机 GPU 默认共驻，不干预非本实验进程

- **级别**：必须
- **范围**：本机 GPU 实验的取卡、启动、计量和截止清理
- **陈述**：默认使用空闲显存共驻；启动前与每次子进程 spawn 前只读核对物理 UUID 与协议预声明的余量门槛。
  外部 PID 只记录，不作为拒绝依据；禁止对非本实验进程发送任何信号，禁止实现冻结/终止/抢占他人作业的
  自动化、常驻轮询守护或自动调度。独占需求须先取具名授权，且不因此获准干预邻居。只读门槛不足时有限等待
  或停止，不能通过腾卡扩展授权；截止清理只针对本轮直接创建、仍持有句柄的子进程。
- **依据**：E-216（2026-10-01 用户决定默认共驻；修复轮预声明 ≥2048 MiB、有限等待及禁止信号边界）；
  决策 `0026-shared-gpu-coresidency-policy.md`
- **现状**：A 类 —— 本轮新修订路径按此政策实施；历史独占守卫与 v1 失败产物保留原样，不回溯改写
- **执行方式**：协议与代码审阅、CPU/fake-CUDA 定向反证、执行时只读设备记录；无全仓机械检查或信号拦截，
  不声称 `check_conventions.py` 能观察运行时的邻居干预
- **例外**：具名独占授权仅改变占用方式，不豁免禁止非本实验信号；历史归档按其原政策只读审计
- **引入日期**：2026-10-01
- **复核触发**：改变设备拓扑、余量查询接口或独占需求，或共驻干扰导致失败时

## N1 v2 的工程参数（不是科学判据）

- 启动选卡：任一卡 `memory.free ≥2048 MiB`；两卡均不足时只读等待间隔 ≤60s、总时长 ≤600s，仍不足停止。
- 每次 spawn：核对已绑定 UUID 的 `memory.free ≥2048 MiB`，保留读时点与外部 PID；不足停止，不能跳任务。
- allocator 峰值只属于本进程；共驻墙钟影响记录到 limitations，不剔除测量值、不放宽逐行零基线。
- GPU ≤0.25h、整轮 ≤1200s 是 N1 v2 当轮的具名工程上限，不是未来实验的通用时限。探针与30次原val评估范围
  见 `docs/goals/n1-cost-supplement-repair.md`；后续实验先完成工程门禁，按决策 0026/0029 共驻并自主声明时长契约。
